OpenClaw Control Model is ready for team review

We now have a fork-only OpenClaw proposal for a headless, framework-neutral control layer that lets products such as Lobster render their own UX without reimplementing Gateway behavior.

OpenClaw owns the model; Lobster owns the experience

Canonical behavior
OpenClaw owns session and conversation state, reconnect reconciliation, typed commands, artifact lifecycle, authorization, and compatibility.

Client-selectable views
OpenClaw core and installed extensions expose every authorized applicable view descriptor. Lobster chooses a compatible view and maps it into M's existing SessionView vocabulary.

Bounded materialization
OpenClaw does not eagerly compute every presentation. Cheap views may be inline; expensive or sensitive views materialize only after the client selects one.

Preserved trust boundary
Native renderers remain host-registered and schema-validated. Actions return through typed model commands and Gateway authorization; third-party executable UI remains sandboxed through MCP Apps.
