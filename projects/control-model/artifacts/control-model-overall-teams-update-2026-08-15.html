OpenClaw primitives can now power a Lobster-owned native UX

Why this exists

We want Lobster/M to own the React experience without importing or forking OpenClaw's Lit Control UI. OpenClaw remains authoritative for sessions, conversation behavior, boards, configuration semantics, authorization, and persistence; Lobster owns product composition, Fluent UX, tenant integration, telemetry, and rollout.

Mission: expose framework-neutral OpenClaw client models so multiple hosts can render their own UX without independently rebuilding raw Gateway reconciliation.

Where we are

Chat and sessions — demonstrated end to end
Lobster consumes canonical session and conversation snapshots for native rendering, streaming, tools, artifacts, actions, send, abort, reconnect, and selected-session history. React remains passive and does not parse raw Gateway events.
RFC 0029  ·  Control UI proof OC4  ·  Lobster proof LM6

Settings — native read-only proof complete
A Lobster settings category now reads selected OpenClaw-authored values and schema/reload metadata through Electron-owned transport. Raw config and write authority never enter React. Governed writes remain blocked on Managed Configuration provenance, locking, preview, generation, and activation.
M design issue #5675  ·  updated RFC evidence

Dashboards and widgets — reusable model proven
OpenClaw's existing board reconciliation is now extracted into an optional Gateway Client model while Control UI remains the reference adopter. Lobster should consume this model rather than reconstruct dashboards from chat artifacts. Native adoption waits for a board-capable OpenClaw/LobsterClaw generation because the pinned 2026.6.33 stack predates the board protocol.
Board Model design and evidence  ·  M adoption plan

Proof: the bounded OC1-OC4 and Lobster L0/LM1-LM6 series, plus the Board Model and Config Model follow-ups, are implemented as review-clean fork-only evidence. This demonstrates the architecture; it does not yet represent released or shipped package support.
