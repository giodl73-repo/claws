OpenClaw Feeds

Expert review and collaboration brief across OpenClaw, ClawHub, Scout, and MOS3

Build a safe, open feed system for discovering, following, verifying, installing, and updating extensions—while keeping discovery, trust, approval, and installation as distinct decisions.

Purpose

This document summarizes what Gio has built and proposed, what remains in flight, and where a feeds expert's judgment would help. It is not a work assignment or ownership-transfer request. The requested contribution is expert advice: challenge the architecture, review the protocol and PR boundaries, identify missing failure modes, and recommend how Gio should simplify or sequence the work. Gio remains responsible for PR ownership and follow-through.

Safety invariants: following is not trust or installation; authenticity, integrity, approval, and runtime trust are separate; installs use exact approved versions; rollback is rejected; refresh retains previous-good state and never widens access.

Scalable catalog distribution

ClawHub #3005, #3149, #3160, and #3163 cover dormant signing, durable history, signed query/change transport, and sharded snapshots. OpenClaw #110250 consumes signed sharded catalogs. The producer PRs are mergeable but currently unstable; #3005 has changes requested. Signing must remain dormant until key custody, rotation, and activation ownership are agreed.

OpenClaw #110438 adds local marketplace watches and can follow the main publisher CLI landing.

Recommended sequence

  1. Align RFC #39 and the protocol vocabulary.
  2. Repair the ClawHub publisher producer through a signed revisioned projection.
  3. Rebuild and land OpenClaw #109305 as the CLI vertical.
  4. Add Gateway lifecycle (#109461), then UI (#109584).
  5. Stabilize scalable catalog production and OpenClaw #110250.
  6. Add local watches; introduce named/shared feeds only after publisher feeds are deployed.

Future composition

Publisher feeds should be the first durable primitive. Later personal, shared/group, tenant, and named feeds can become ACL-controlled effective views. For Microsoft, MOS3 should own stable feed identity, revisions, signatures, scope/RBAC, inclusion provenance, exact versions, pins, denies, revocations, exceptions, preview, explain, and audit. Lobster remains an adapter; file feeds remain development/test/bridge mechanisms.
