# Awesome Claws 50-Package Expansion

This expands the portfolio from 35 to 50 finished agent applications while
introducing Experience (`X`) as the seventh private review dimension. The new
Claws fill distinct jobs and demonstrate useful output surfaces; they do not
exist only to exercise a schema field or dashboard control.

## Experience Rules

- Portable packages use existing role-labeled `workspace.files` for HTML/SVG
  shells, Markdown fallbacks, schemas, examples, fixtures, and other assets.
- Packaged visual assets are inert and reviewable: no embedded credentials,
  remote script dependencies, automatic network calls, or hidden mutations.
  Host APIs are feature-detected and every action remains understandable when
  those APIs are absent.
- `AGENTS.md` owns the output contract and explains when an asset is consumed.
- OpenClaw-specific `show_widget` and `dashboard` grants live only in
  `profiles/openclaw.yml`; they are not new portable manifest fields.
- Every visual result has a complete text/artifact fallback. Unsupported
  clients must lose presentation, not meaning or control.
- Inline results are the default. Pin only state that remains useful across
  turns, and update pinned widgets by a stable package-documented name. The
  first persistent pin is user-initiated or follows an explicit reviewed setup
  preference; an agent does not fill the board merely because it can.
- Widget actions cannot silently mutate external systems. They send an
  explicit prompt or use a separately declared and operator-granted host
  capability.

## Authoring Waves

1. **Wave 7A, Experience foundations:** add an opt-in conformance case registry
   for primary surface, fallback asset, stable widget names, and least-privilege
   OpenClaw grants; author the six pair exemplars. Scores remain private human
   review evidence and are never generated from field counts.
2. **Wave 7B, operational breadth:** add Facilities, Data Migration, Quality
   Assurance, and Cloud Cost applications.
3. **Wave 7C, research and program breadth:** add UX Research,
   Experimentation, Localization, Accessibility, and Fundraising applications.
4. After each wave, materialize the complete catalog and run standalone and
   OpenClaw preview checks for every package. The final wave runs all 50 through
   isolated lifecycle and scenario proof.

## Required Experience Evidence

Each package record names `text`, `artifact`, `inline-widget`, or `dashboard`
as its primary surface and records its fallback. X4/X5 packages additionally
prove:

1. the exact visual asset materialized and was used rather than regenerated
   from an unrelated model pattern;
2. the rendered surface is nonblank, readable at desktop and mobile sizes, and
   contains no overlapping controls or clipped text;
3. the same domain state produces a useful Markdown artifact;
4. stable widget identity updates rather than duplicating a card;
5. X5 pinning survives transcript reset and removal follows session/dashboard
   ownership without leaving unexplained state; and
6. unsupported clients do not receive `show_widget` and still complete the
   scenario through the declared fallback.

Scores and pair assignments remain coordination material in `claws-hapi`.
Public Awesome Claws documentation describes the available experience shapes
without publishing a leaderboard.
