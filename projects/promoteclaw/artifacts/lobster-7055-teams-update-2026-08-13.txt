Quick update on PR #7055

We had several issues in the DoltLite integration that OpenClaw 6.33 exposed, and we have fixed them.

A Git-workspace test was enforcing the wrong contract. It was checking flighted DoltLite persistence in the generic SPO lane. We separated the base Git-workspace smoke from the dedicated flight-enabled persistence proof.

The Playwright recovery path was not actually retrying cleanly. Same-document navigation returned no HTTP response, and outer retries could run past the pooled-user lease. Retries now reset through about:blank and use bounded cold-worker attempts inside the lease.

Merging current main created a Teams lifecycle conflict. We re-derived the newer Teams delivery behavior against the 6.33 patch stack while preserving exact reply correlation, ProxyPipe telemetry, and failed-worker retirement.

The last Runtime run passed 54 checks. The one remaining failure is now narrowed to a specific restored Git workspace, not the 6.33 image generally. Another pooled user starts successfully on the same image. For the failing user, Lobster starts the worker and restores the SPO-backed workspace, but the OpenClaw Gateway exits before ready. Every replacement worker fails against that same restored state.

We have instrumented the lane to preserve and redact the ephemeral worker log before lease cleanup removes the container. Build 176483560 is running with that instrumentation now. It should identify the exact file, config field, or plugin state that 6.33 cannot load. We can then reproduce it locally and add a version-aware migration that preserves the user's data rather than resetting the workspace.
