# Configure Runtime Governance

Set up the governance plugin, governance skill, and GovernanceHost for runtime enforcement.

## Governance Plugin (L2+L3)

The governance plugin provides runtime blocking. It intercepts tool calls and enforces policies before execution:

```
Agent → Tool call → Governance Plugin → Policy check → Allow/Deny → Tool execution
```

The plugin is automatically generated by `claws build` and installed into the workspace's plugin directory.

## Governance Skill (L1 Advisory)

The L1 governance skill provides prompt-level guidance without blocking. It advises agents on governance requirements:

```markdown
# Governance Advisory

## Before using tools

- Check tool classification against your permission tier
- Verify data classification for any accessed entities
- Ensure OBO boundary compliance

## Required checks

- R3+ tools require explicit task authorization
- Confidential data requires elicitation gate approval
- All actions are audit-logged
```

## GovernanceHost Interface

The GovernanceHost exposes 6 facets:

1. **Policy evaluation** -- check if an action is permitted
2. **Tool gating** -- allow/deny tool calls based on classification
3. **Budget enforcement** -- track and limit token usage
4. **Audit recording** -- log all governance decisions
5. **Compliance reporting** -- generate evidence on demand
6. **Health monitoring** -- report governance system status

## Injection Defense

16 rules protect against prompt injection:

```json
{
  "injectionDefense": {
    "enabled": true,
    "rules": "all",
    "action": "block-and-audit"
  }
}
```

Rules cover: direct injection, indirect injection, jailbreak patterns, role confusion, instruction override, tool abuse, data exfiltration, and more.

## A2A Governance

Agent-to-agent governance (FE6) controls how agents communicate across workspace boundaries:

```json
{
  "a2aGovernance": {
    "enabled": true,
    "trustModel": "verify-then-trust",
    "allowedPeers": ["support-workspace", "analytics-workspace"],
    "crossBoundaryAudit": true
  }
}
```

## Hook Lifecycle

OC hooks execute in a defined lifecycle:

```
before_tool_call → policy_check → execute_tool → after_tool_call → audit_record
```

Each hook stage has a latency budget of 50ms. The full hook chain must complete within 200ms.
