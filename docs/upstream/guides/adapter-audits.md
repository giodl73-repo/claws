# Adapter Audits

Companion guide to PR-3 (`@openclaw/guardrails`), PR-4 (OC-7 conjunctive
merger), and PR-5 (`@openclaw/policy`) of the `claws-openclaw-upstream`
contribution wave. Records the verdicts of the two adapter audits the
wave depends on:

1. **Emitted-plugin registration** — does the gateway plugin generated by
   `@openclaw/policy` (PR-5) register cleanly via today's
   `PluginHookRegistration` shape and CLI dispatcher? (§2)
2. **Audit-stream wire-shape** — does the audit-event envelope emitted by
   `@openclaw/guardrails/audit` (PR-3) map cleanly into CEF / NDJSON /
   syslog / SARIF without truncating critical evidence? (§3)

§4 documents the **runtime-gated enforcement model** — explicit because
without OC-1/OC-2 hooks, file governance is runtime-gated, not
write-blocked, and consumers' threat models must reflect that.

## §1 Purpose

The wave merges three packages (`@openclaw/workspace`, `@openclaw/guardrails`,
`@openclaw/policy`) plus surgical OC-4 + OC-7 PRs into upstream. Two
adapter surfaces span our packages and upstream's runtime: the plugin
registration boundary and the audit-event boundary. If either drifts from
upstream's actual shape, downstream PRs land with broken integrations and
the bot-reviewer trio (Greptile + Copilot + chatgpt-codex) will reject
them on type errors or behavioral mismatches.

This guide is the **pre-flight audit record**. PR-3 and PR-5 must cite the
verdict here in their PR descriptions. If a future audit reveals shape
drift on trunk, this guide is amended _first_ and the dependent PR delays
until the adapter is corrected.

## §2 Emitted-plugin registration audit

### §2.1 Current upstream registration shape

Source of truth at `openclaw-core: src/plugins/hook-types.ts:936-942`
(HEAD `dd643c82b`, 2026-04-28):

```ts
export type PluginHookRegistration<K extends PluginHookName = PluginHookName> = {
  pluginId: string;
  hookName: K;
  handler: PluginHookHandlerMap[K];
  priority?: number;
  source: string;

```

Hook names enumerated at `hook-types.ts:70-105` (`PluginHookName` union)

35 hook names total spanning lifecycle (`session_start`, `agent_end`,

registration boundary takes a `pluginId` from authenticated caller —
**must not** trust payload-supplied id (per F-01 / BOT-P-001).

The shape **matches** `PluginHookRegistration` exactly (5 fields, optional

### §2.3 Sequential-modifying-mode vs claim-mode

Hook handlers run in **sequential modifying mode** for hooks that mutate
the request flow (per upstream merger semantics — see PR-4 / OC-7 scope).
The merger at `src/plugins/hooks.ts:889-893` accumulates results from
plugins in priority order; OC-7 changes the merger from `??` (first-wins)
to array accumulation (conjunctive). The generated plugin produces single
results that the merger accumulates with siblings — it does **not**
assume claim-mode (where one plugin "wins" and others skip). PR-5 tests
must exercise the multi-plugin path explicitly so a sequential-merger
regression doesn't silently change semantics. (F-34 / ADP-PR-002.)

### §2.4 CLI subcommand registration shape

Upstream uses **Commander** (`commander@^14.0.3`, declared at
`openclaw-core: package.json:1599`). Plugin CLI registration goes through:

- **Loader**: `src/plugins/cli.ts` —
  `loadPluginCliDescriptors`, `loadPluginCliRegistrationEntriesWithDefaults`
- **Registrar**: `src/plugins/register-plugin-cli-command-groups.ts:32` —
  `registerPluginCliCommandGroups(program, entries, params)` accepts an
  `eager | lazy` mode, a primary-command name, and an `existingCommands`
  set for collision avoidance
- **Root CLI shape**: `src/cli/argv-invocation.ts:resolveCliArgvInvocation`
  parses argv into a structured invocation (commandPath, primary,
  hasHelpOrVersion). The `program: Command` parameter is a Commander root
  passed in from `src/cli/`.

Sample handler emitted by `@openclaw/policy` for the `openclaw policy <verb>`
subcommand group:


## §3 Audit-stream wire-shape audit (PR-3 hard dependency)

### §3.1 Background

Upstream openclaw-core today has a **security-audit findings** surface
(`src/security/audit-channel.ts`) that produces dedup'd findings about
config security posture (DM policy openness, account-level allowlist
gaps, dangerous-name matching). It does **not** today publish a
general-purpose audit-event stream (lifecycle / approval / promote /
mutation events with hash-chain integrity). That gap is exactly what
`@openclaw/guardrails/audit` ships in PR-3 — net-new substrate, not a
replacement.

The wire-shape audit therefore covers two transitions:

1. `@openclaw/guardrails/audit` internal `AuditEntry` shape
2. SIEM-format outputs (CEF / NDJSON / syslog / SARIF)

Both must round-trip cleanly: an entry written and re-read produces the
same `AuditEntry`. SIEM parsers downstream cannot truncate evidence-
bearing fields, or SOC 2 CC7.2 audit-log-coverage is not provable.

### §3.2 `AuditEntry` canonical shape

```ts
export interface AuditEntry {
  readonly schemaVersion: 1;
  readonly eventId: string; // ULID or UUIDv7
  readonly timestamp: string; // RFC 3339 with millisecond precision
  readonly eventType: AuditEventType;
  readonly actor: AuditActor; // see §3.3
  readonly sourcePluginId: string; // mandatory — adversarial-defense (W6)
  readonly correlation: {
    readonly sessionId?: string;
    readonly runId?: string;
    readonly approvalHandleId?: string;
  };
  readonly payload: Readonly<Record<string, unknown>>;
  readonly chain: {
    readonly previousHash: string;
    readonly entryHash: string; // sha-256 over canonicalized entry-without-this-field
  };
}
```

`AuditEventType` is the discriminated union covering: `approval.issued`,
`approval.resolved`, `approval.expired`, `snapshot.promote`,
`snapshot.supersede`, `snapshot.rollback`, `policy.violation.detected`,
`policy.gate.invoked`, `tool.call.allowed`, `tool.call.denied`,
`workspace.mutation.unauthorized`, `runtime.error`. New event types
extend the union as `@openclaw/policy` and `@openclaw/snap` mature.

### §3.3 Field-by-field mapping table (the F-38 HC-BLOCK gate)

The table below is the round-trip contract. Every SIEM formatter
re-parses to the original `AuditEntry`; deviations require this table to
be amended first, a regenerated round-trip test, and re-review.

| `AuditEntry` field             | CEF                                              | NDJSON                                  | syslog                                                                     | SARIF                                                                          |
| ------------------------------ | ------------------------------------------------ | --------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| `schemaVersion`                | `cs1Label=schemaVersion cs1=1`                   | `"schemaVersion": 1`                    | `[schemaVersion@1 v="1"]`                                                  | `version: "1.0"` (plus tool.driver.semanticVersion)                            |
| `eventId`                      | `cs3Label=eventId cs3=<ulid>`                    | `"eventId": "<ulid>"`                   | `[eventId@1 id="<ulid>"]`                                                  | `result.guid: "<ulid>"`                                                        |
| `timestamp`                    | `rt=<rfc3339-ms>`                                | `"timestamp": "<rfc3339-ms>"`           | timestamp prefix per RFC 5424                                              | `result.message.markdown` includes; canonical in `result.properties.timestamp` |
| `eventType`                    | `cat=<eventType>`                                | `"eventType": "<eventType>"`            | `[event@1 type="<eventType>"]`                                             | `result.ruleId: "<eventType>"`                                                 |
| `actor.principalId`            | `suser=<principalId>`                            | `"actor.principalId": "..."`            | `[actor@1 user="<principalId>"]`                                           | `result.properties.actor.principalId`                                          |
| `actor.principalType`          | `cs2Label=principalType cs2=<type>`              | `"actor.principalType": "..."`          | `[actor@1 type="<type>"]`                                                  | `result.properties.actor.principalType`                                        |
| `sourcePluginId`               | `cs4Label=sourcePluginId cs4=<id>`               | `"sourcePluginId": "..."`               | `[plugin@1 id="<id>"]`                                                     | `result.properties.sourcePluginId`                                             |
| `correlation.sessionId`        | `cs5Label=sessionId cs5=<id>`                    | `"correlation.sessionId": "..."`        | `[correlation@1 session="<id>"]`                                           | `result.properties.correlation.sessionId`                                      |
| `correlation.runId`            | `cs6Label=runId cs6=<id>`                        | `"correlation.runId": "..."`            | `[correlation@1 run="<id>"]`                                               | `result.properties.correlation.runId`                                          |
| `correlation.approvalHandleId` | `cn1Label=approvalHandleId cn1=<id>`             | `"correlation.approvalHandleId": "..."` | `[correlation@1 approval="<id>"]`                                          | `result.properties.correlation.approvalHandleId`                               |
| `payload`                      | concatenated as `msg=<json>` (truncated at 30KB) | `"payload": { ... }` (full)             | `[payload@1 json="<...>"]` (truncated at 16KB per syslog message-size cap) | `result.properties.payload`                                                    |
| `chain.previousHash`           | `cs7Label=previousHash cs7=<sha256>`             | `"chain.previousHash": "..."`           | `[chain@1 prev="<...>"]`                                                   | `result.properties.chain.previousHash`                                         |
| `chain.entryHash`              | `cs8Label=entryHash cs8=<sha256>`                | `"chain.entryHash": "..."`              | `[chain@1 hash="<...>"]`                                                   | `result.properties.chain.entryHash`                                            |

### §3.4 Timestamp granularity (F-39)

All formats emit **RFC 3339 with millisecond precision** (e.g.
`2026-04-28T14:30:45.123Z`). CEF's `rt` field is documented as either
epoch-millis or RFC 3339 — we standardize on the latter for cross-format
parity. SIEM parsers that expect epoch-millis must convert; we document
this limitation in §3.7.

### §3.5 Actor identity / `suser` mapping (F-40)

CEF `suser` (source user) maps to `actor.principalId`. The
`actor.principalType` (e.g., `human`, `agent`, `system`, `cron`) goes into
custom string `cs2`. SIEMs that don't honor custom strings will lose the
type discriminator; they retain the principalId for audit-trail purposes.
Documented in §3.7.

### §3.6 Correlation field convention (F-41)

The `cs3` slot is canonically reserved for `eventId` across all
formatters. Per-event correlation (`sessionId`, `runId`,
`approvalHandleId`) goes into `cs5`/`cs6`/`cn1` respectively. Downstream
SIEMs that aggregate by `cs3` will get clean event-grouping without
configuration. The convention is encoded in
`@openclaw/guardrails/siem/formats/cef.ts` constants.

### §3.7 Lossy-format tradeoffs (F-43)

| Format | Loss                                                                  | Mitigation                                                                               |
| ------ | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| CEF    | Custom-string slots cap at 8 (`cs1`-`cs8`); fields beyond are dropped | NDJSON is the canonical full-fidelity format; CEF is for SIEM ingestion only             |
| CEF    | `msg` field truncated at 30KB by some SIEM ingesters                  | Long payloads trigger a `payload.truncated: true` marker; full payload remains in NDJSON |
| syslog | Message-size cap (typically 16KB per RFC 5424)                        | Payload truncated with marker; structured-data fields preserved                          |
| SARIF  | Not a streaming format — built for static-analysis output             | Used for export at `snap export --format sarif`, not for live audit ingestion            |

### §3.8 Round-trip integrity (F-38 — the HC-BLOCK)

For each format, the contract is:

```ts
const written = formatCef(entry); // or formatNdjson, formatSyslog, formatSarif
const reparsed = parseCef(written); // recovers AuditEntry
assert.deepEqual(reparsed, entry);
```

Lossy formats (CEF, syslog) return a **partial** `AuditEntry` on re-parse
— guaranteed-recoverable fields are: `eventId`, `timestamp`, `eventType`,
`actor.principalId`, `sourcePluginId`, `chain.previousHash`,
`chain.entryHash`. Non-guaranteed fields under lossy formats include
`payload`, `correlation.sessionId/runId/approvalHandleId` if their
encoded form exceeds the format's cap. Tests live at
`packages/openclaw-guardrails/tests/integration/round-trip-{format}.test.ts`.

### §3.9 `--verify` flag for `snap export` (F-42)

`snap export --verify --format <fmt>` re-verifies the audit chain
_before_ formatting any entry. Tampered chains exit non-zero with
`OC_AUDIT_CHAIN_TAMPERED <position>`. Without `--verify`, export proceeds
on potentially-stale chains — useful for testing but warned in the CLI
help text.

## §4 Runtime-gated enforcement model (F-45)

**This is not write-blocked. This is runtime-gated.**

The original UG-upstream v0.1 plan proposed OC-1 / OC-2 / OC-6 hooks that
would have allowed write-time prevention of unauthorized workspace-file
mutations. Those hooks were dropped from the v0.2 contribution roadmap.
The replacement enforcement model relies on `before_agent_start`, which
fires **after** files load — at the start of an agent turn, not on
filesystem write.

### §4.1 Event flow

```
1. Attacker writes malicious edit to SOUL.md / TOOLS.md (mutates filesystem)
2. Agent turn begins; framework loads workspace files
3. before_agent_start fires; @openclaw/policy plugin compares
   workspace's current snapshotId to the LAST PROMOTED snapshotId
4. If drift: plugin emits requireApproval with reason
   "unauthorized SOUL.md mutation since last promote"
5. Agent stalls until supervisor approves or workspace is rolled back
6. Without `snap stage on`, files remain on disk; rollback is via
   `snap rollback`
7. With `snap stage on`, edits are parked in `.openclaw/.stage/` and
   never reach canonical until promote
```

### §4.2 What this catches

- Mutations between agent turns when the workspace drifts
- Promote without explicit user action (snapshot drift)
- Rollback bypasses (snapshot mismatch detected)

### §4.3 What this does NOT catch

- The mutation event itself (filesystem write succeeds)
- Side effects of the mutation that occurred between write-time and the
  next agent turn (e.g., a cron job that read the mutated file already)

### §4.4 Threat model

Consumers that require **write-time prevention** (e.g., regulated tenants
where the workspace is treated as a write-protected canonical) deploy
`@openclaw/snap` in **`stage on` posture**. In stage-on, all writes are
intercepted and parked in a staging directory; promote requires explicit
user approval. The runtime gate then becomes a defense-in-depth layer
under the staging layer.

Consumers without `stage on` accept that:

- Mutations land on disk
- The next agent turn detects drift via `before_agent_start`
- Recovery is `snap rollback` to the last promoted snapshot

This is **runtime-gated enforcement**, not write-blocking. Threat models
of the consuming product must reflect that mutations briefly exist on
disk before detection. Audit chain entries
(`workspace.mutation.unauthorized`) record the drift for forensics.

### §4.5 Forensic detail

When the gate fires, the audit entry includes:

- `oc://` URI of the mutated file (e.g.,
  `oc://SOUL.md/Boundaries/deny-rule-1`)
- Hash of the previous-known content
- Hash of the current content
- Timestamp of detection (NOT of the original write — that timestamp is
  not always recoverable post-hoc)
- The agent turn's `runId` for correlation

Multiple drifted files are reported in separate entries (one per file),
not bundled, so SIEM correlation works per-file. (F-47, F-48.)

### §4.6 Performance bound

Gate compares hashes only for files in the **policy-relevant set** —
`SOUL.md`, `TOOLS.md`, `AGENTS.md`, `IDENTITY.md`, `USER.md`, `SKILL.md`,
plus any file referenced by an active `args_from` chain. Files outside
this set (e.g., user prose documents) are not hashed on every agent turn.
(F-49.)

## §5 Re-audit cadence

This guide is the **frozen snapshot** of the adapter audits at the time
of PR-3 / PR-5 push. After each upstream PR merges:

- **Run the post-merge verification runbook**
  (`docs/upstream/guides/post-merge-verification.md`) against trunk
- **Re-check the citations in §2.1, §2.4, §3** against the new HEAD
- **Record deltas** in `docs/upstream/CHANGELOG.md`

Concrete triggers for re-audit (any of these → re-audit before next PR):

- `src/plugins/hook-types.ts` changes the `PluginHookRegistration` shape
  (new field, renamed field, type change)
- `src/plugins/register-plugin-cli-command-groups.ts` changes its public
  API
- A new SIEM format is added to `@openclaw/guardrails/siem/formats/`
- `@openclaw/guardrails/audit` adds a new `AuditEventType`

The cadence is **event-driven**, not time-based — an audit re-run when
none of the triggers fire produces no new information.
