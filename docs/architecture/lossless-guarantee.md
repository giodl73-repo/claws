# The Lossless Guarantee

<!-- atom:lossless-guarantee (C11) -->

## Overview

claws never modifies original workspace files. This is the foundational architectural constraint: byte-for-byte round-trip preservation of every file the developer authored. The compiler reads workspace files, produces governance artifacts in `.claws/`, and emits platform-specific output. No source file is written to, overwritten, or reordered. The lossless guarantee makes claws safe to adopt -- running `claws build` cannot corrupt a project.

---

## Write-Allow-List

The EMIT phase enforces a write-allow-list. Only files on the allow list can be written during compilation:

| Path                  | What is written          | Why allowed                                   |
| --------------------- | ------------------------ | --------------------------------------------- |
| `.claws/`             | All pipeline artifacts   | Compiler-owned output directory               |
| Platform config files | Governance sections only | Delimited injection (CLAUDE.md, .cursorrules) |

**Source files are read-only**: the compiler opens source files (SOUL.md, AGENTS.md, TOOLS.md, etc.) with read-only file handles. No write handle is acquired for any source file at any pipeline stage.

**Reserved directory collision check**: the `.claws/` directory may contain a generated governance skill. If the generated skill directory name collides with a user-authored skill directory, claws raises a compile-time error rather than overwriting. P-230 (generated skill directory name collision) prevents this.

**Platform config exceptions**: for platforms like Claude Code and Cursor, claws writes governance sections to config files (CLAUDE.md, .cursorrules) using delimiter-based injection. Content outside the delimiters is preserved. This is the only case where claws writes to files the developer may have authored, and it is scoped strictly to the delimited region.

## Raw vs Normalized Hashing

claws uses two distinct hash types to support both lossless verification and incremental compilation:

| Hash type          | Input                                           | Purpose                                                    |
| ------------------ | ----------------------------------------------- | ---------------------------------------------------------- |
| Raw-byte SHA-256   | Unmodified file bytes                           | Lossless verification -- proves the file was not changed   |
| Normalized IR hash | LF-normalized, BOM-stripped, sorted-key content | Incremental compilation -- determines if re-emit is needed |

**Why two hashes?** A single hash cannot serve both purposes. The raw hash must include BOM and CRLF to prove the file is untouched. The normalized hash must exclude BOM and CRLF to allow cross-platform cache sharing (P-233: CRLF vs LF hash divergence breaks cache sharing).

**Deterministic serialization**: the normalized hash depends on deterministic output. claws enforces:

- Sorted-key JSON serialization (`JSON.stringify` with sorted replacer)
- Lexicographic file path ordering for processing
- GovernanceIR hash excluding timestamps and ambient state
- Compiler version in IR metadata for cache invalidation on upgrade

P-234 (non-deterministic JSON serialization breaks idempotence) drove the sorted-key requirement.

## Cross-Platform Determinism

The same workspace must produce the same governance output on Windows, macOS, and Linux. Cross-platform determinism requires:

### BOM Handling

- UTF-8 BOM (`0xEF 0xBB 0xBF`) is stripped before keyword anchor extraction (P-232: BOM causes first constraint to be missed)
- UTF-16 BOM is detected and transcoded to UTF-8 without writing back to the source file
- BOM stripping in Node.js uses explicit byte comparison, not string methods that may vary
- `claws.json` on Windows may contain BOM -- the parser accepts JSON with BOM

### Line Ending Normalization

- CRLF source files are normalized to LF for IR hashing (not for source file storage)
- Mixed line endings (CRLF, LF, CR in the same file) are normalized consistently
- Generated files follow the workspace line ending convention or force LF (configurable)
- Line/column mapping accounts for CRLF when reporting diagnostic positions

### File Processing Order

- File paths are sorted lexicographically before processing
- Directory traversal order (OS-dependent) is never relied upon
- Deterministic processing order ensures reproducible GovernanceIR output

## Compiled Workflow Detection

P-231 (compiled workflow fed back as source) prevents feedback loops. If a developer renames a compiled output file to match a source file name, the next build would read compiled governance as source input, compounding injected rules.

claws's PARSE phase detects compiled workflows by checking for the ownership comment header (`// Generated by claws -- do not edit`) and skips them as source input.

---

## Error Recovery

When compilation fails, the lossless guarantee extends to error handling:

| Failure mode                   | Behavior                                                       |
| ------------------------------ | -------------------------------------------------------------- |
| Parse error in one file        | Other files still compile; per-file error collection           |
| EMIT phase crash               | Last-known-good artifacts preserved (P-235)                    |
| Zero successfully-parsed files | Graceful exit with diagnostic; no artifact deletion            |
| Unhandled exception            | Atomic staging ensures partial writes do not corrupt `.claws/` |

The last-known-good preservation is critical. A failed build must never delete previously-emitted artifacts. The developer's last working governance enforcement remains active while they fix the error.

---

## Scope

The lossless guarantee applies to workspace files -- the 9 files the developer authors (SOUL.md, AGENTS.md, TOOLS.md, etc.). Pipeline state in `.claws/` is owned by the compiler and may be overwritten. The distinction is explicit: workspace files are the developer's property; `.claws/` is the compiler's workspace.

`claws pinch --fix` is scoped to non-source files only. `claws doctor --fix` takes a mandatory snapshot before modifying any file.
