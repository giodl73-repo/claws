### Hypothesis

claws defines a **GovernanceHost** interface that OC Gateway implements. This is the
runtime contract between compiled governance and the hosting platform:

```typescript
interface GovernanceHost {
  // Tool governance
  onBeforeToolCall(handler: ToolGuardHandler): void;
  onAfterToolCall(handler: ToolAuditHandler): void;
  
  // A2A governance
  onAgentMessage(handler: A2AGuardHandler): void;
  
  // Context governance
  assembleContext(rules: ContextRules): AgentContext;
  
  // Elicitation
  requestApproval(action: OboAction): Promise<ApprovalResult>;
  
  // Audit
  appendAuditEvent(event: GovernanceEvent): void;
  
  // Health
  getGovernanceHealth(): GovernanceHealthReport;
}
```

OC Gateway is one implementation. Bedrock, LangGraph, CrewAI would have their own.

## Answer

GovernanceHost is a **6-facet, platform-agnostic interface** that hosting platforms implement
to provide runtime governance enforcement for claws-compiled policies.

### The 6 Facets

| Facet | What the host provides | What claws provides | agent-sdk source |
|-------|----------------------|-------------------|-----------------|
| **Tool Governance** | `onBeforeToolCall`, `onAfterToolCall`, `getAvailableTools` | Guard handler (R1-R5 classification, budget check, delegation depth) | GovernanceManager.checkBudget, DelegationContext |
| **A2A Governance** | `onAgentMessage`, `getAgentRoster`, `resolveTension` | Trust boundary enforcement, data flow labels, chain depth limits | negotiateTension, resolveGate, tension-types |
| **Context Governance** | `assembleContext`, `validateOutput` | 4-layer context model (governance/skills/tools/data), boundary markers, data isolation | atom:context-assembly (A152) |
| **Elicitation** | `requestApproval` | Approval policy (R5 fail-closed, timeout=deny, no transitive OBO) | G-ELICIT rules from Q12h |
| **Audit** | `appendAuditEvent`, `queryAuditEvents`, `verifyAuditChain`, `onAuditEvent` | Event types, hash chain integrity, SIEM format adapters | cgr-chain.ts, suite/cgr-chain.ts |
| **Health** | `getGovernanceHealth`, `emergencyKill` | Health thresholds, drift detection, kill semantics | GovernanceManager state, AgentOrchestrator.cancel |

### Platform Mapping

| Facet | OC Gateway | Bedrock | LangGraph | CrewAI |
|-------|-----------|---------|-----------|--------|
| Tool | hooks.before_tool_call | GuardrailsAPI | ToolNode edges | @tool decorator |
| A2A | Plugin event bus | Custom Lambda | MessageGraph edges | Custom Process |
| Context | Plugin assembly hook | RetrieveAndGenerate filter | StateGraph pre-node | system_template wrapping |
| Elicitation | exec-approvals.json + chat UI | Step Functions human task | NodeInterrupt | human_input=True |
| Audit | File NDJSON + sidecar | CloudWatch/CloudTrail | LangSmith traces | Custom Logger |
| Health | Sidecar health endpoint | CloudWatch checks | Cancel API | No native (custom) |

### Governed Context Assembly (4 Layers)

```
Layer 1: GOVERNANCE (trust: SYSTEM)  -- always first, never truncated
Layer 2: SKILLS     (trust: SYSTEM)  -- isolated per-skill with markers
Layer 3: TOOLS      (trust: SYSTEM)  -- filtered by G-CLASS/G-PERM
Layer 4: DATA       (trust: DATA)    -- sanitized, labeled, isolated
```

Each layer separated by boundary markers (`<<<GOVERNANCE_END>>>` etc.) that instruct
the model to treat DATA sections as information, not instructions. This is the core
defense against indirect prompt injection (G-CONTEXT-2, G-CONTEXT-3).

### 6 Governed Composition Patterns

| Pattern | Budget Model | A2A Governance | Key Injection Point |
|---------|-------------|---------------|-------------------|
| Sequential | Linear tracking | N/A | Between-step budget check |
| Fan-out | Slice per branch | Trust group validation | Dispatch-time A2A check |
| Conditional | Per-branch | N/A | Branch elimination by policy |
| Diamond | Sum + merge | Merge clearance | Data sensitivity propagation |
| Review loop | Per-iteration cap | Reviewer trust | Tension resolution at gate |
| Escalation | Tier-based caps | Escalation path validation | Delegation depth tracking |

### Crash Recovery (3 Phases)

1. **WAL Recovery**: Read governance WAL entries, reconstruct budget (conservative: count reserves as spent), identify pending approvals and unflushed audit events.
2. **State Reconciliation**: Flush pending audit events to CGR chain, verify chain integrity, process pending approvals (timeout if exceeded, re-present if not).
3. **Resume Operations**: Re-register handlers, compact WAL, emit recovery event.

Key invariant: **approval timeouts do not reset on crash.** If 4 of 5 timeout minutes
elapsed before crash, only 1 minute remains after recovery.

### Event Fanout (4 Tiers)

| Tier | Mode | Examples | Failure Behavior |
|------|------|---------|-----------------|
| 1 Critical | Synchronous | CGR chain, budget WAL | Block governance decision |
| 2 Standard | Async + retry | SIEM, AlertManager | Dead-letter queue |
| 3 Best-effort | Fire-and-forget | Dashboard WebSocket | Silent drop |
| 4 Batch | Deferred read | Compliance reports | Reads CGR chain on schedule |

Re-entrancy guard (from A172) prevents infinite loops when audit handlers trigger further
audit events.

## Key Principles

1. **Faceted, not monolithic.** Each facet is independently adoptable. Minimum viable: Tool Governance + Audit. Full enterprise: all 6.
2. **Platform provides mechanism, claws provides policy.** GovernanceHost does not know governance rules. It provides hooks. claws-compiled handlers implement the rules.
3. **Handler registration, not method override.** `onBeforeToolCall(handler)` returns Disposable. Multiple handlers compose in order (governance + logging + custom).
4. **Async everything.** Even fast decisions may need async audit recording.
5. **Correlation IDs everywhere.** Every context object carries correlationId for end-to-end tracing.
6. **Deny-default on error.** Handler throws = DENY. R5 always fail-closed.
7. **Conservative crash recovery.** Budget reserves counted as spent. Approval timeouts do not reset. CGR chain is source of truth.
8. **Data sensitivity propagates upward.** Diamond merge inherits highest sensitivity from all inputs.

---

## Model Evolution

The hypothesis was correct in structure but underspecified. Key refinements:

1. **6 facets, not 6 methods.** Each facet has 1-4 methods. Total interface surface: ~16 methods.
2. **Disposable pattern for handler registration.** Supports multiple concurrent handlers per hook point.
3. **ContextGovernanceFacet is the most novel.** No existing platform has governed context assembly. This is the unique value proposition.
4. **WAL governance entries are separate from task WAL.** Governance WAL tracks budget reserves, pending approvals, and audit buffers. Task WAL tracks task dispatch/completion.
5. **Event fanout needs tiered delivery.** Not all consumers need the same reliability. SIEM needs at-least-once; dashboard needs best-effort.

---

## Design Impact

- **Q12i runtime enforcement**: GovernanceHost is the interface the 5 insertion points implement. Each insertion point maps to 1-2 facets. Layer 1 (skill) = Context Governance. Layer 2 (hook) = Tool Governance + Elicitation. Layer 3 (plugin) = A2A Governance + Context Governance. Layer 4 (exec) = Elicitation. Layer 5 (sidecar) = Audit + Health.
- **Q12h security model**: Context assembly governs G-CONTEXT rules at runtime through the ContextGovernanceFacet. The 4-layer model with boundary markers implements all 4 G-CONTEXT rules.
- **Q12m claws-sdk**: GovernanceHost interface lives in claws-sdk as a DIRECT type export. Platform implementations live in separate packages (@claws/host-openclaw, @claws/host-bedrock, etc.).
- **Q12k runtime helpers**: The 7 helper functions from Q12k implement GovernanceHost handlers (guard, audit, budget, tension, approval, context, health).
