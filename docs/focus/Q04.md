# Q12d: What is the right CLI name if the tool governs beyond OpenClaw?

**Priority**: High
**Status**: Proposed
**Owner**: giodl
**Resolves**: CLI naming when scope includes OpenClaw agents + managed agents (Claude, Cursor, GitHub Copilot, custom); "claw" branding vs neutral branding; whether `claws` is too narrow
**Blocks**: Final CLI name, package name (@craftworks/?), all Q12a-Q12c naming references
**Experiments**: a, b (2 total, 2 complete)

---

## Question

Q12c designed a 35-command verb surface for `claws` — the "claw compiler." The entire naming
chain (claws, .claws/, claws.json, pinch, snap) derives from the OpenClaw "claw" metaphor.

But what if this tool also governs **managed agents** — Claude Code agents, Cursor agents,
GitHub Copilot workspaces, custom enterprise agents? The cross-compilation targets (SU-04)
already exist: `claws build cursor`, `claws build claude`, `claws build github`. If a
platform engineer governs 20 Claude agents and 5 OpenClaw agents, does "claw compiler"
still feel right?

Two tensions:

1. **Brand clarity vs scope**: `claws` is memorable and ties to OpenClaw's ecosystem. But
   if 60% of governed agents aren't OpenClaw, the name misleads.
2. **Community positioning vs neutrality**: Contributing to OpenClaw upstream (Q12b) is
   easier when the tool name signals claw-native. A neutral name signals independence —
   which could be strength (platform play) or weakness (no ecosystem home).

### Hypothesis

A neutral name that works across all agent platforms while keeping crustacean/governance
flavor where earned. The verb surface (pinch, snap, --fleet) can survive a name change
if the base name is platform-agnostic. Candidates to evaluate: `claw` (shorter, still
claw-adjacent), `grip`, `carc` (carapace compiler), `agc` (agent governance compiler),
or something entirely different.

### What Survives a Name Change?

The verb surface from Q12c was designed to be largely platform-agnostic:
- `build`, `compile`, `test`, `diff`, `init`, `doctor` — universal
- `pinch` — governance enforcement, claw metaphor but could work standalone ("pinch point")
- `snap` — snapshot shorthand, claw metaphor but also generic ("snap" = quick capture)
- `--fleet`, `--skip-pinch` — flags are name-independent
- `scan`, `broadcast`, `drift`, `kill` — standard ops verbs

The verbs survive. The question is only the base CLI name.

## Answer

**`glint` — governance for every agent. 5 chars, "governance lint" embedded, modern DX energy (ruff/bun/vite tier), pinch/snap survive, fully cross-platform from day one.**

### Resolution

The CLI name is `glint`. Config: `glint.json`. Artifacts: `.glint/`. Package: `@craftworks/glint`.

| Element | Value | Why |
|---------|-------|-----|
| CLI binary | `glint` | "Governance lint" embedded. Modern, short, sticker-worthy. |
| Config file | `glint.json` | Per-workspace governance config |
| Artifact directory | `.glint/` | Governance artifacts, cache, audit chain |
| Package | `@craftworks/glint` | Scoped to avoid collision with @glint/core (Ember) |
| Verb surface | 35 commands (unchanged from Q12c) | pinch, snap, --fleet all survive |

### Why glint wins

| vs | Why glint wins |
|----|---------------|
| `claws` | claws is OC-native but weakens as managed agents join. glint is platform-agnostic from day one. |
| `grip` | grip is workmanlike where glint sparkles. grip sounds like a 2018 K8s tool. |
| `seal` | seal is enterprise-corporate. glint is community-first with enterprise growing in. |
| `fence` | fence is governance-perfect but personality-zero. It kills pinch. |
| `conch` | conch is memorable but pronunciation wars hurt adoption. |

### The adoption Trojan horse

Developers install glint thinking "a linter for my agents" — low friction, familiar mental model. Run `glint pinch`, get pass/fail in 0.3s. Feels like eslint or ruff.

Then governance takes over: audit trails, compliance evidence, fleet scanning, budget enforcement, SIEM export. The "lint" mental model lowers the adoption barrier. By the time the CISO is involved, glint IS the governance platform.

### Collision note

`@glint/core` exists (Ember/Glimmer TypeScript tooling). Completely different domain. The scoped package `@craftworks/glint` avoids npm collision. The binary name `glint` may conflict on systems with the Ember tool installed — mitigated by scoped install path and different user population (Ember developers ≠ agent governance engineers).

### Bottom line

`glint` scores 8.2/10 on the community-modern-fun-extensible rubric — highest of 16 candidates. It nails platform extensibility (9), community vibe (9), and modern DX (9) while getting governance signal for free. The name is pending boss approval — if rejected, the runner-ups are `conch` (7.3), `grip` (7.1), and `seal` (7.1). The verb surface and command map are name-independent.

## Key Principles

### b: The "lint" Trojan horse is a feature, not a bug

- Governance tools that announce themselves as governance get rejected by developers ("not my job")
- Tools that feel like linters get adopted, then governance expands from within
- `glint` starts as a type-check, ends as the enterprise control plane
- The adoption funnel: lint → audit → comply → fleet → the CISO is asking for the dashboard

> **Principle: Name your governance tool for the developer who installs it, not the CISO who buys it.** Adoption flows bottom-up. The name must clear the developer's "do I need another tool?" filter.

### a: Cross-platform positioning requires a platform-neutral name

- 7 managed platforms exist, zero have compile-time governance — the market is cross-platform
- `claws` scores 5/10 on platform extensibility (signals OpenClaw-only)
- `glint` scores 9/10 — works equally for OpenClaw, Claude, Cursor, Bedrock, any agent
- The verb surface (pinch, snap, --fleet) is name-independent and survives any rename
- Crustacean verbs work WITH a neutral name — they add flavor without limiting scope

> **Principle: When your tool governs multiple ecosystems, the name must be welcome in all of them.** A claw-branded tool governing Claude agents creates a "why am I using their tool?" moment. A neutral name with ecosystem-specific flavor verbs avoids this.

## Design Impact

- **Q12a-Q12c**: All `claws` references → `glint` (config, directory, command examples). Verb surface unchanged.
- **Q12b**: Upstream packages stay `@openclaw/` scope. CLI package is `@craftworks/glint`. No conflict.
- **SU-04/05/06**: External-facing command surface now in `design/suite/GLINT-MAP.md`. Internal SDK mapping unchanged.
- **GLINT-MAP.md**: Created as authoritative external command reference (parallel to COMMAND-MAP.md for internal).
- **Marketing**: "glint — governance for every agent" replaces "claws — the claw compiler"
- **Community**: Cross-platform positioning. OpenClaw is the starting ecosystem, not the only one.
