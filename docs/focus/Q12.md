## Question

Q12k designed the three-tier package model (@openclaw/* + @claws/runtime + @craftworks/*).
Now the practical question: what exactly does claws extract from Craftworks?

Key discoveries from the codebase audit:

### Already exists — governance compilation infrastructure

```
compiler-sdk/src/astro/ir/
  governance/governance-relax-compile.ts   ← Governance IR with RELAX!
  policy/policy-ir.ts                      ← Policy IR (the policy language!)
  policy/policy-compiler.ts                ← Policy COMPILER (already built!)
  policy/policy-relax-compile.ts           ← Policy rules as RELAX expressions
  tool/tool-relax-compile.ts               ← Tool classification via RELAX
  tier/tier-relax-compile.ts               ← Trust tier rules via RELAX
```

This is NOT extraction from scratch. **The governance compilation pipeline already exists.**
claws is a new frontend that wires up existing IRs to new emitters.

### PRESS → pinch mapping

PRESS (compiler-sdk/src/astro/ir/press/) has:
- `bipartite-split.ts` — split content into keep/compress sections
- `quality-matrix.ts` — score content by quality dimensions
- `token-counter.ts` — count and budget tokens
- `rewrite-rules.ts` — transform content by rules
- `position-optimizer.ts` — optimize content positioning
- `press-profiles.ts` — named optimization profiles
- `cache-contract.ts` — caching semantics

**pinch** (governance check) needs the same pipeline:
- Split workspace into governed/ungoverned sections (bipartite-split)
- Score tools by risk dimensions (quality-matrix → risk-matrix)
- Count/budget governance overhead (token-counter → governance-counter)
- Transform violations by rules (rewrite-rules → fix-rules)
- Optimize rule ordering for fast checking (position-optimizer → rule-optimizer)
- Named governance profiles: soc2, hipaa, minimal (press-profiles → pinch-profiles)
- Cache governance results (cache-contract)

### Cache infrastructure

`compiler-sdk/src/astro/cache/optimization-cache.ts` — cache for compiled outputs.
claws needs the same for:
- Compiled governance IR (`.claws/cache/compile/`)
- Boost/optimization cache (`.claws/cache/boost/`)
- Evaluation cache (`.claws/cache/eval/`)
- Snapshots (`.claws/cache/snapshots/`)

### Report infrastructure

`compiler-sdk/src/astro/emit/reports/` has emitters for:
- Markdown, HTML, JSON, PDF, TUI, ADM (Adaptive Document Model)

OC users need governance reports in these formats:
- `claws comply soc2` → markdown/HTML/PDF compliance report
- `claws report` → fleet dashboard (TUI or JSON)
- `claws audit export` → CEF/JSON/syslog (already in Q12h)

### Audit chain

`compiler-sdk/src/astro/audit/audit-chain.ts` — hash-chained audit log.
This IS the `@openclaw/audit-chain` contributed package.

### Hypothesis

claws doesn't extract FROM Craftworks — it's a new FRONTEND for existing Craftworks
infrastructure. The governance IRs, policy compiler, RELAX integration, cache, reports,
and audit chain already exist. claws adds:

1. New readers for OC workspace files → governance-specific intent extraction
2. New emitters for TypeScript skills/plugins/workflows
3. New CLI surface (35 commands from GLINT-MAP)
4. New runtime library (@claws/runtime)
5. New contributed packages (@openclaw/*)

The "lift and shift" is:
- **Share** (import from compiler-sdk/agent-sdk): governance IR, policy compiler, RELAX, cache, reports, audit, readers, emitters
- **Create new**: claws CLI, intent extractors, TS/Python emitters, runtime library, contributed packages
- **Leave**: everything else (80+ modules)

## Answer

**glint does not extract FROM Craftworks -- it is a new frontend for existing Craftworks
infrastructure.** The governance compilation pipeline already exists. glint adds a new CLI
surface, new intent extractors, new emitters, and a shared library ecosystem (@claws/*).

### Skill Package Compilation

`glint build` emits complete installable OC skill packages:

```

  package.json          -- @claws/* as peer deps
```

Distribution: ClawHub marketplace, private npm registries, `glint broadcast --packages`.

### Package Model: Monorepo Workspace

glint-cli is a new workspace in the Craftworks monorepo (alongside craft-cli, guard-cli,
fleet-cli, forge-cli). Same thin-CLI pattern: command registrations import from SDKs.

**Why monorepo**: glint imports ~55 modules from 3 SDK packages. Version synchronization,
type-checking, single `npm install`, shared CI. Standalone repo cost > separation benefit.

@claws/* libraries CAN be extracted to standalone repos later -- they have clean, minimal
dependency surfaces. The glint CLI stays in the monorepo.

## Key Principles

1. **No extraction, just a new frontend.** The governance IR, policy compiler, RELAX engine,
   audit chain, cache, and report infrastructure already exist. glint wires them up with
   new readers, emitters, and a CLI surface.

2. **Three-tier package model (from Q12k).** Generated code imports @openclaw/* and @claws/*,
   never @craftworks/*. The Craftworks SDK is invisible to OC users.

3. **Libraries before compiler.** @claws/* packages work without glint. Any OC developer
   can `npm install @claws/relax`. The compiler is the top of the funnel; the libraries
   are the ecosystem.

4. **PRESS generalizes, not forks.** 5 of 7 PRESS modules can be reused with type parameters
   and injectable configuration. The optimization primitives are domain-agnostic.

5. **Peer dependencies for generated packages.** @claws/* libraries are peer deps of generated
   skill packages. Deduplication, version consistency, small package size.

## Model Evolution

| Version | Model | Change |
|---------|-------|--------|
| Q12 | "claws extracts from Craftworks" | Initial framing: extraction |
| Q12k | "Three-tier package model" | Package architecture |
| **Q12l** | **"glint is a new frontend + .NET for OpenClaw"** | **Shift from extraction to frontend + shared libraries** |

The key evolution: from "what do we extract?" (extraction mindset) to "what do we expose?"
(platform mindset). glint doesn't take anything from Craftworks -- it adds a new surface
that exposes existing capabilities to the OC ecosystem through standalone @claws/* libraries.

## Design Impact

- **CODEBASE.md**: Add `glint-cli/` as 10th package in monorepo workspace list
- **compiler-sdk**: No structural changes. New IR subdirectory for GovernanceIR. New emitters for TypeScript skill output and Python guards. New intent extractors. PRESS modules gain generic interfaces (backward-compatible).
- **agent-sdk**: No changes. glint imports govern/, hashing/, diffgram/, execute/delegation-guard, eval/, suite/audit, suite/gates, discovery/ as-is.
- **craftworks-sdk**: No changes. glint imports governance/ and domains/fleet/ subset.
- **Q12b upstream**: @openclaw/* packages (5) wrap existing modules. Separate npm packages, MIT license.
- **PRESS spec**: Generalize bipartite-split, quality-matrix, rewrite-rules, press-profiles, cache-contract to accept type parameters and injectable configuration. Non-breaking.
