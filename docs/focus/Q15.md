## Question

claws has two faces:

1. **Governance** (protect): classify, pinch, comply, audit — the security/compliance story
2. **Maker** (create): scaffold, generate, test, publish — the developer productivity story

Q12a-Q12m designed the governance face. This question designs the MAKER face.

Today, OC skill development is:
- Write SKILL.md by hand (freeform markdown)
- Optionally add TypeScript handler (no framework, no testing harness)
- `openclaw skills check` (basic validation)
- `clawhub publish` (no governance validation)

With claws, skill development becomes:
- `claws new skill email-drafter` → scaffolds typed skill with governance annotations
- `claws build` → generates TypeScript handler from SKILL.md spec
- `claws test` → runs generated tests against scenarios
- `claws pinch` → validates governance before publish
- `claws publish` → publishes with governance badge to ClawHub

### Hypothesis

@bic/claws-skill-kit is the standard development framework for OC skills. It provides:

1. **Scaffolding**: `claws new skill <name>` generates a complete skill directory with
   SKILL.md template, TypeScript handler skeleton, test fixtures, package.json, governance
   annotations (risk level, capabilities, OBO flags, data labels)

2. **Code generation**: `claws build --skill` reads SKILL.md and generates:
   - Typed handler functions from tool declarations
   - Test cases from skill scenarios
   - OBO approval flows from elicitation annotations
   - Audit chain integration from governance config

3. **Testing framework**: `@bic/claws-test` provides:
   - Skill scenario runner (mock Gateway, mock tools)
   - Governance validation (does the skill satisfy its declared policy?)
   - Security scanning (injection patterns, secret detection)
   - Performance benchmarks (latency budget validation)

4. **Publishing pipeline**: `claws publish` wraps `clawhub publish` with:
   - Pre-publish governance check (must pass `claws pinch`)
   - Governance badge (verified by claws, risk level declared)
   - Signed manifest (provenance, integrity)
   - Dependency audit (checks @claws/* and other deps)

5. **Adoption path for existing skills**: Existing skills add governance incrementally:
   ```yaml
   # Add to SKILL.md frontmatter:
   governance:
     risk: R3
     capabilities: [READ, WRITE]
     obo: [send-email]
     data: [INTERNAL]
   ```
   Three lines → governance-aware. No code changes required.

## Working Notes

### Today's OC skill structure

```
my-skill/
  SKILL.md          ← freeform markdown + YAML frontmatter
  (optional: handler.ts, package.json, tests/)
```

### With claws skill-kit

```
my-skill/
  SKILL.md          ← typed frontmatter with governance annotations
  src/
    handler.ts      ← generated OR hand-written, with @bic/claws-skill-kit decorators
    types.ts        ← generated from tool declarations
  tests/
    scenarios.test.ts  ← generated from SKILL.md scenarios
    governance.test.ts ← governance validation tests
  package.json      ← @bic/claws-skill-kit as dep
  claws.json        ← governance config (optional, inherits workspace)
  .claws-manifest   ← build provenance, signed
```

### The decorator pattern

```typescript
import { skill, obo, audit, classify } from '@bic/claws-skill-kit';

export default skill('email-drafter', {
  risk: 'R3',
  capabilities: ['READ', 'COMMUNICATE'],
  
  @classify('send-email', { risk: 'R5', obo: true })
  @obo({ mode: 'inline', timeout: 300 })
  @audit()
  async sendEmail(to: string, subject: string, body: string) {
    // claws generates the approval flow around this
    return await tools.email.send({ to, subject, body });
  }
});
```

## Answer

@bic/claws-skill-kit is the standard development framework for OC skills. It provides a complete maker experience from scaffolding to publishing, with governance woven into every step. The key design decisions:

**1. skill() factory + decorators**: The `skill()` function defines OC-compatible skills with typed handlers. Six decorators (@obo, @audit, @classify, @validate, @budget, @timeout) annotate handlers with governance behavior. Decorators are metadata -- claws reads them at build time and generates the governance wrapper code. The developer writes business logic; claws writes plumbing.

**2. SKILL.md as source of truth**: `claws build --skill` compiles SKILL.md through a 5-phase pipeline (PARSE -> EXTRACT -> ANALYZE -> GENERATE -> EMIT) producing typed interfaces from tool declarations, governance wrappers from annotations, test cases from scenarios, and OBO flows from governance.obo. Two developer-owned files (SKILL.md + src/handler.ts), everything else generated. Build time: ~10-20ms.

**3. @bic/claws-test framework**: Four testing layers -- scenario runner (plays SKILL.md scenarios against the built skill), governance validator (12 checks verifying declared vs actual behavior), security scanner (16 rules across injection/secret/eval/input categories), and custom vitest matchers for governance assertions. MockGateway + MockTools + MockApproval for local testing without a real OC Gateway.

**4. Three-tier adoption path**: Existing 5,198 skills adopt claws incrementally:
- **Tier 1 (DECLARED)**: Add governance frontmatter to SKILL.md. 2-5 minutes, zero code changes, zero risk. Gets ClawHub badge + fleet scan visibility.
- **Tier 2 (TYPED)**: Import @bic/claws-skill-kit, use skill() + decorators. 15-30 minutes. Gets type safety + construction-time governance validation.
- **Tier 3 (VERIFIED)**: Full claws build with generated types, tests, governance wrapper, signed manifest. 30-60 minutes (automated by `claws import`). Gets maximum enterprise trust.

**5. OC-native design**: Generated code imports from @openclaw/* (Tier 1 packages) and @claws/runtime (Tier 2 helpers). No @craftworks/* imports ever appear in generated output. An OC developer reading the generated skill understands it without knowing Craftworks exists.

**6. Publishing pipeline**: `claws publish` wraps `clawhub publish` with pre-publish governance check (must pass pinch + test), signed manifest, dependency audit, and governance badge metadata. ClawHub displays governance badges (DECLARED/TYPED/VERIFIED) with risk level, OBO actions, and data classification.

## Key Principles

1. **SKILL.md is the contract.** Everything flows from SKILL.md: types, governance wrappers, tests, badges. Two files to own (SKILL.md + handler.ts), everything else generated.

2. **Decorators are metadata, not behavior.** @obo, @audit, @classify annotate handlers but don't execute at runtime. claws reads decorator metadata at build time and generates the actual governance code.

3. **Governance is progressive.** The three-tier model means every skill can start at Tier 1 (3 lines of YAML) and graduate to Tier 3 (full compilation) at its own pace. No skill needs a rewrite to benefit.

4. **Generated code passes the OC developer test.** If an OC developer can read the generated code and understand it without knowing Craftworks exists, the design is correct. If they see WorkAgentSupervisor, RELAX, or DataFrames, the design has leaked.

5. **claws complements, never replaces.** `claws publish` calls `clawhub publish`. `claws pinch` is a superset of `openclaw skills check`. The OC-native workflow still works.

## Model Evolution

The hypothesis held with two refinements:

1. **Decorator syntax clarified**: The working notes showed decorators applied to object literal methods, but TypeScript 5.0 decorators require class methods. The design uses class-based handlers with decorators, wrapped by the `skill()` factory function.

2. **Adoption path quantified**: The three-tier model was always the intent, but exp-e added concrete metrics: Tier 1 takes 2-5 minutes, Tier 2 takes 15-30 minutes, Tier 3 takes 30-60 minutes. `claws annotate` (Tier 1) and `claws import` (Tier 3) automate the majority of migration work.

## Design Impact

- **CLAWS-MAP**: Adds 4 new commands: `claws new skill` (scaffold), `claws publish` (governed publish), `claws annotate` (suggest governance), `claws import` (migrate existing skill). Total command surface: 39 commands (up from 35 in Q12c).
- **Q12c verb surface**: `new`, `publish`, `annotate`, `import` are standard compiler verbs. No new crustacean verbs needed.
- **Q12k packages**: @bic/claws-skill-kit (~35KB) and @bic/claws-test (~45KB) become the 12th and 13th @claws/* packages.
- **ClawHub**: Governance badge requires additive metadata in the publish API payload. No schema changes -- ClawHub renders governance section when present.
- **Q12b upstream**: @bic/claws-skill-kit is claws-scoped, not contributed upstream. @openclaw/* packages (Q12b) remain the upstream contribution.
- **Q12n mapping**: The three-tier adoption model maps directly to the 5,198 skill ecosystem analyzed in Q12n. Enterprise adoption policy can require DECLARED for R1-R2, TYPED for R3, VERIFIED for R4-R5.
