# Q12c: What is the right verb surface for claws?

**Priority**: High
**Status**: Proposed
**Owner**: giodl
**Resolves**: Command naming for the unified claws CLI; verb audition for all 40 commands; crustacean naming theme; progressive disclosure tiers; --fleet scope model integration
**Blocks**: claws CLI implementation, SU-04/05/06 OpenClaw mapping, claws --help design
**Experiments**: a (1 total, 1 complete)

---

## Question

Q12a established: one CLI (`claws`), `claws.json` config, `.claws/` directory, `--fleet` scope
flag, `pinch` as governance enforcement verb. Q12 experiment e defined 40 commands across
two CLIs (23 clawsc + 17 clawops) mapping to craft (16), guard (6), and fleet (25).

Now merge these into one verb surface that feels **first-class for OpenClaw** — not a thin
wrapper over craft/guard/fleet internal names. The verbs should:

1. Feel native to the claw/crustacean ecosystem (claws, pinch, molt, shell, etc.)
2. Follow the `{language}c` compiler convention (rustc, javac → claws)
3. Support `--fleet` scope escalation on scope-sensitive commands
4. Support progressive disclosure (Maker 4 cmds → Developer 14 → Advanced 23+)
5. Make governance a first-class verb, not an afterthought

### Hypothesis

The 40 commands collapse into ~30 with crustacean-themed verb groups: `claws build` (compile),
`claws pinch` (govern), `claws molt` (evolve/transform), `claws shell` (protect/harden),
plus standard verbs (init, test, diff, doctor). Fleet operations use `--fleet` flag on
scope-sensitive commands, with inherently-fleet commands (scan, broadcast, drift) having no
workspace equivalent.

### Bare Invocation (4-Step Quick Start)

```
$ claws

  claws — the claw compiler
  Compile, govern, and operate OpenClaw agents.

  Quick start:
    claws init                   Set up governance for your workspace
    claws build                  Compile and emit your agent
    claws pinch                  Check against your org's policies
    claws build cursor           Cross-compile to another platform

  Run 'claws --help' for all commands.
```

### The Crustacean Naming Rule

Only 2 of 35 verbs use crustacean names. The rule: **standard verbs for standard actions, crustacean verbs only when they're shorter AND more evocative than the standard alternative.**

| Crustacean verb | What it replaces | Why it wins |
|-----------------|-----------------|-------------|
| `pinch` | check, guard, lint | "Pinch your workspace through the governance fences." 5 chars, no collision with `guard` CLI, carries the claw identity. |
| `snap` | snapshot | 4 chars vs 8. Claw snap = quick capture. Earned brevity. |

Every other command uses the standard verb: `build`, `compile`, `test`, `diff`, `audit`, `comply`, `scan`, `kill`. Forcing crustacean metaphors on standard actions (`molt` for compile, `shell` for protect, `reef` for fleet) was tested and rejected — they add cognitive load without adding clarity.

### The `--pinch` / `--skip-pinch` Flags

Governance is the default. `claws build` auto-triggers a pinch check. Two flags control this:

```bash
claws build                              # build + auto-pinch (default)
claws build --skip-pinch                 # build without governance check
claws build cursor --optimize --pinch    # explicit: build + optimize + pinch
claws snap save v2 --pinch              # snapshot with governance validation
```

`--pinch` is explicit opt-in (on commands that don't auto-pinch). `--skip-pinch` is explicit opt-out. This is shift-left governance: the developer must consciously choose to skip enforcement.

`claws` (bare) shows 4 commands. `claws --help` shows 18. `claws --help-all` shows 35.

### Scope Model (6 Scope-Sensitive Commands)

| Command | Default | --fleet available? | --confirm required? |
|---------|---------|-------------------|-------------------|
| `pinch` | workspace | Yes | No |
| `comply` | workspace | Yes | No |
| `snap save/restore` | workspace | Yes | No |
| `budget` | workspace | Yes | No |
| `kill` | workspace | Yes | **Yes (--fleet)** |
| `snap diff` | workspace | Yes | No |

Inherently-fleet commands (scan, broadcast, drift, report, push) don't need `--fleet` — the action implies the scope. Inherently-workspace commands (build, compile, test, ...) don't accept `--fleet` — they operate on files.

### Bottom Line

35 commands, 8 groups, 2 crustacean verbs. `pinch` carries the governance identity. `snap` earns its brevity. Everything else uses the standard verb the user already knows. Governance is the build default — you opt out, not in. Progressive disclosure hides fleet and snapshot complexity until the user needs it. The whole surface maps cleanly to craft/guard/fleet SDK calls as a thin UI adapter.

## Key Principles

### a: Only 2 of 35 verbs earn crustacean names — clarity beats theme

- `pinch` (governance) and `snap` (snapshot) are the only crustacean verbs in the surface
- `molt` was considered for compile/amend but implies whole-agent transformation, not targeted change
- `shell` was considered for protect/harden but collides fatally with terminal "shell"
- `reef` was considered for fleet/colony but requires explanation where `scan` is instant
- Standard verbs (`build`, `test`, `audit`, `comply`, `kill`) are terms of art — CISOs expect "audit", developers expect "build"
- The crustacean naming rule: shorter AND more evocative than the standard alternative, or don't use it

> **Principle: Theme vocabulary must earn its place by being shorter or more vivid than the standard term.** Forcing metaphors onto established terms of art damages the first-impression test with every persona.

## Follow-Up Questions

1. **Q12c-F1**: Should glint support custom verb aliases? → **Resolved: No.** One verb per action. Aliases create confusion ("is `check` the same as `pinch`?"). Instead: provide migration guides for teams coming from other tools. `pinch` IS the governance verb — learning one word is cheaper than maintaining alias tables.
2. **Q12c-F2**: Should `glint --help` adapt to workspace context? → **Resolved: Yes, progressive.** If no fleet config exists, fleet commands in `--help-all` show as grayed/annotated "(requires fleet setup)". The developer tier (`--help`) already hides fleet commands. This is progressive disclosure applied to context, not just persona.
3. **Q12c-F3**: Should `glint pinch` support rule-level filtering? → **Resolved: Yes.** `glint pinch --only G2,G4` and `glint pinch --skip G1` are natural flags for iterative remediation. Added to GLINT-MAP cross-cutting flags. Matches how eslint `--rule` works.
4. **Q12c-F4**: Tab completion structure? → **Resolved: Group-first.** `glint audit<TAB>` → verify, export, history. `glint s<TAB>` → scan, secrets, session, snap. Matches the 8-group command structure. Subcommands complete after the group verb, not in a flat namespace.
5. **Q12c-F5**: Plugin/extension verb for third-party rules? → **Deferred to post-v1.** `glint ext install my-policy` or `glint plugin add` is the right shape. Important for third-party governance rules and policy marketplace. Not MVP — ship the core 35 commands first, add extensibility when community demand is validated.
