# Platform: LangGraph

<!-- atom:platform-langgraph (C11) -->

## Overview

LangGraph is a Python-first agent framework. claws detects LangGraph workspaces via `langgraph.json` configuration files, emits governance as Python guard code (not TypeScript), and supports Human-in-the-Loop (HITL) integration for OBO elicitation gates. LangGraph is the first platform requiring claws's multi-language code generation architecture.

---

## Detection

LangGraph detection uses the `langgraph.json` configuration file:

| Marker | Detection role |
|--------|---------------|
| `langgraph.json` | Primary -- LangGraph project configuration |
| Config content inspection | JS vs Python distinction from dependencies and entry points |

The JS vs Python distinction is critical. LangGraph supports both JavaScript and Python runtimes. claws inspects the config content (not just filename) to determine which language to target. P-241 (LangGraph Python output but claws only emits TypeScript) drove this requirement -- defaulting to TypeScript for a Python framework produces unusable guard decorators.

Without `langgraph.json`, LangGraph requires explicit target declaration in `claws.json`. A workspace using LangGraph without the config file is not auto-detected.

## Python Code Generation

claws's multi-language code generation architecture emits Python guard code for LangGraph targets:

```python
# Generated by claws -- do not edit
from claws_guard import before_tool, deny, elicit

@before_tool("send_email")
def guard_send_email(ctx):
    if ctx.tool.obo:
        return elicit(ctx, reason="OBO boundary: sends as user")
    return deny(reason="R5 tool requires elicitation gate")
```

The Python guard package (`claws-guard`) is shared between LangGraph and CrewAI platforms. It provides the `@before_tool` decorator, deny/allow/elicit primitives, and audit logging.

**Code generation ordering**: guard functions are emitted in lexicographic order by tool name. This ensures deterministic output across builds, supporting the lossless idempotence guarantee.

## HITL Integration

LangGraph has native Human-in-the-Loop support via interrupt nodes. claws maps OBO elicitation gates to LangGraph's HITL mechanism:

| claws concept | LangGraph equivalent |
|---------------|---------------------|
| Elicitation gate | Interrupt node with approval callback |
| Deny-default timeout | Interrupt timeout with deny result |
| Approval token | LangGraph state update with signed approval |

This integration means that R5/OBO tools on LangGraph have stronger enforcement than on advisory platforms (Cursor, Copilot). The LangGraph runtime actually pauses execution and waits for human input, rather than relying on the LLM to follow instructions.

## Performance Budgets

Platform-specific performance budgets constrain guard code overhead:

| Operation | Budget | Rationale |
|-----------|--------|-----------|
| Guard evaluation (per tool) | < 10ms | Must not perceptibly delay tool invocation |
| HITL interrupt setup | < 50ms | Interrupt node creation overhead |
| Audit log write | < 5ms | Async write, non-blocking |

These budgets apply to the emitted Python code, not to the compilation pipeline. The compilation pipeline has its own budget (200ms for ANALYZE phase).

## LangChain Tool Bridging

LangGraph tools may be defined as LangChain `Tool` or `StructuredTool` instances. claws's supplementary parsing for LangGraph includes tool model bridging -- extracting tool metadata from LangChain tool definitions to build the tool classification table. This ensures that tools defined via LangChain's abstractions receive proper risk classification.
