### Major (M)

| #   | File                                            | Line/Section                          | Finding                                                                                                                                                                                                                                                                                                                                                                                                                           | Suggested fix                                                                                                                                                                                                                                                                                                                        |

| M1  | claws-cli/src/commands/watch.ts                 | 62 (AnthropicLLMProvider constructor) | **New Anthropic client created per extract call.** `AnthropicLLMProvider.extract()` calls `importSdk()` and then instantiates `new Anthropic({ apiKey, ... })` on every single extraction. In watch mode this means every debounced LLM cycle spins up a new HTTP client with fresh connection pools. Over an 8-hour watch session this is a slow resource leak — TCP sockets and TLS sessions are never reused.                  | Move client construction to the provider constructor (or a lazy singleton). The `importSdk()` cache already exists for the module; extend the pattern to cache the client instance as well. Validate API key once at construction, not per-call.                                                                                     |
| M2  | claws-cli/src/commands/watch.ts                 | 152-202                               | **Async work inside setTimeout without unhandled-rejection guard.** The `setTimeout` callback is `async` — if it throws after the `AbortError` check (e.g., a network timeout that is not an AbortError and `opts.verbose` is false), the rejection is silently swallowed because `setTimeout` does not track promise rejections. On Node 18+ unhandled rejections terminate the process, which would crash the watcher silently. | Wrap the entire `setTimeout` body in a `try/catch` at the outermost level, or move the async work to a named async function and call it with `.catch(handleError)` inside the timeout. The current catch only handles `AbortError` and verbose-mode logging — a non-Error throw or an error in the result-storage path would escape. |
| M3  | claws-sdk/src/compile/llm/anthropic-provider.ts | 56-111                                | **No client reuse across calls — connection pool thrash.** Each call to `extract()` creates a `new Anthropic(...)` client. The Anthropic SDK maintains internal connection pools. Recreating per-call means no HTTP keep-alive, no connection reuse, higher latency on every extraction. For `extractAll()` (which loops sequentially over N files), this is N cold TCP handshakes instead of 1.                                  | Construct the client once in the provider constructor. Store as `private readonly client: Anthropic`. The API key can be validated at construction time (`throw` early if missing) — this also eliminates the per-call `process.env` read.                                                                                           |

If 4 files change at once, the debounce callback blocks for 4x the API latency (~30s per file worst case = 120s). | W7  | claws-sdk/src/compile/llm/extractor.ts | 73-88             | **No cancellation support in `extractAll`.** The `extractAll` method loops sequentially but accepts no `AbortSignal`. The `ExtractionOptions` type has a `signal` field but it is not threaded through `extractAll`.                                                                                                                                                 | Accept an `AbortSignal` parameter and check `signal.aborted` between iterations, or pass it through via `options`.                                                                                                                                                                                            |

---

## Summary

The LLM extraction pipeline correctly isolates itself behind the `--llm` flag — without it, zero runtime cost is incurred (N3). The watch debounce design (200ms window, cancel-on-new-edit) is sound. However, three issues warrant fixing before merge: the Anthropic client is reconstructed per-call causing connection pool thrash in watch mode (M1/M3), and the async setTimeout in the debounce path risks unhandled promise rejections that could crash the watcher (M2). The raise-only risk invariant is silently ineffective for overlapping intents because the LLM risk class is never passed to `raiseOnlyRisk` (W5) — this is a security-adjacent concern that the ciso panel should also flag.
