## Findings

### Major (M)

| # | File | Line/Section | Finding | Suggested fix |
|---|------|-------------|---------|---------------|
| M1 | claws-cli/src/cli.ts | L182-202 | **Watch command bypasses `createLLMProvider` and constructs `AnthropicLLMProvider` directly in the CLI command handler.** All other commands (compile, check, build, extract) delegate LLM provider creation to `core/llm.ts:createLLMProvider`, which validates `ANTHROPIC_API_KEY` and handles SDK-missing errors. The watch handler directly imports `AnthropicLLMProvider` from the SDK and constructs it inline, skipping all validation. This violates two boundaries: (1) the SDK-owns-logic rule — env-var validation is a domain concern, and (2) the established adapter pattern where `core/llm.ts` is the single creation path. If the API key is missing, watch will proceed and crash deep inside the Anthropic SDK instead of producing a clean error. | Route `watch` through `createLLMProvider` and pass the resulting `LLMProvider` to `runWatch`, matching the pattern used by compile/check/build. |
| M2 | claws-cli/src/cli.ts | entire file | **`claws cache` subcommands (status, export, import, clear) are defined in `commands/cache.ts` but never registered in the Commander.js program.** The functions `runCacheStatus`, `runCacheExport`, `runCacheImport`, `runCacheClear` exist and are fully implemented, but no `cache` command or its subcommands are wired in `cli.ts`. Running `claws cache status` will print the help screen. This blocks the CP-5 exit criteria: "claws cache export / claws cache import round-trips." | Add a `cache` subcommand group in `cli.ts` with `status`, `export`, `import <file>`, and `clear` sub-subcommands, following the same pattern as `snap` and `keys`. |
| M3 | claws-cli/src/commands/compile.ts, build.ts, check.ts | compile:117-125, build:175-180, check:107-114 | **LLM extraction results are extracted but never verified or merged.** All three commands call `llmExtractor.extractAll()` and then discard the results except for counting them in verbose output. The verifier (`verifyExtractionResult`) and merger (`mergeIntents`) — which enforce the raise-only security invariant — are never invoked. This means `--llm` produces no governance effect: the LLM intents are computed, logged, and thrown away. The compile pipeline still runs on regex-only intents. This blocks CP-5 exit criteria: "LLM can only raise risk, never lower (security invariant verified by test)." | Wire the verifier and merger into the compile pipeline: verify LLM results against source content, merge verified intents with regex intents using `mergeIntents`, and feed the merged set into the AST/manifest construction. |
| M4 | claws-sdk/src/compile/llm/merger.ts | L195, L203 | **`raiseOnlyRisk` always receives `undefined` as the second argument for overlapping intents.** When regex and LLM find the same intent, the code calls `raiseOnlyRisk(existingRegex.riskClass, undefined)` — the LLM intent has no `riskClass` field (the `LLMIntent` type does not carry one). This means `raiseOnlyRisk` always returns the regex risk unchanged. The LLM can never raise risk on overlapping intents, defeating the security invariant for the most common merge case. | Either: (a) extend `LLMIntent` to carry an optional `riskClass` derived from the LLM's classification, or (b) pass a separate risk-mapping function that infers risk from LLM confidence/kind, and feed that into `raiseOnlyRisk`. |

### Warning (W)

| # | File | Line/Section | Finding | Suggested fix |
|---|------|-------------|---------|---------------|
| W1 | claws-sdk/src/compile/llm/anthropic-provider.ts | L55-112 | **`AnthropicLLMProvider.extract()` creates a new `Anthropic` client on every call.** The `importSdk()` call caches the module, but the `new Anthropic({ apiKey, baseURL })` constructor runs on every `extract()` invocation. For `extractAll()` which calls `extractFile()` sequentially across all workspace files, this means 4-6 fresh client instances per compile. The SDK constructor may set up HTTP agents, auth headers, and retry config each time. | Move client construction to the `AnthropicLLMProvider` constructor (lazy-initialize on first use if the SDK is optionally resolved). Cache the client instance as a private field. |
| W2 | claws-sdk/src/compile/llm/extractor.ts vs prompts/ | extractor.ts:57-64, prompts/ | **`ExtractorLLM` uses generic `prompts.ts` instead of file-specific prompts.** The `extractFile()` method passes the raw `entry.source` and `entry.content` to `provider.extract()`, which in `AnthropicLLMProvider` uses the generic `buildSystemPrompt`/`buildUserPrompt` from `prompts.ts`. The 4 file-specific prompts in `prompts/` (SOUL, TOOLS, AGENTS, SKILL) are exported through the barrel but never invoked anywhere in the extraction pipeline. They provide significantly better extraction quality (structured intent categories, confidence guidelines, adversarial guards) but are dead code. | Route extraction through file-specific prompts based on `entry.source` filename matching (e.g., `SOUL.md` -> `buildSoulSystemPrompt()`). The generic prompt becomes the fallback for unknown file types. |
| W3 | claws-sdk/src/compile/llm/anthropic-provider.ts | L57-59 | **API key is read from `process.env` on every `extract()` call rather than once at construction.** If the env var is removed mid-session (unlikely but possible in watch mode), one call succeeds and the next fails with a confusing error. More importantly, this means the provider cannot be validated at construction time — callers must wait for the first `extract()` call to discover the key is missing. | Read and validate the API key in the constructor (or in a factory function). Throw early if missing. |
| W4 | claws-sdk/src/compile/llm/cache.ts | L114-115 | **`LLMCache.entries` and `promptHashes` are mutable despite all public types being readonly.** The class fields `entries` and `promptHashes` are `private` but not `readonly` — `entries` is reassigned in `load()` and `clear()`. While this works, it means internal mutation can silently invalidate any external references to `status()` results. For a cache that may be used across async boundaries (watch mode), this is a consistency risk. | Make `entries` and `promptHashes` readonly and use `.clear()` + re-populate instead of reassignment. |
| W5 | claws-sdk/src/compile/llm/index.ts | L24-46 | **Barrel re-exports both generic prompts (`buildSystemPrompt`, `buildUserPrompt`) and file-specific prompts at the same level.** Consumers see `buildSystemPrompt` (generic) alongside `buildSoulSystemPrompt` (specific) without any naming convention or grouping to signal that one is the active pipeline path and the other is currently unused. This will confuse contributors about which prompt path is authoritative. | Either: (a) namespace the file-specific prompts under a `prompts` sub-export, or (b) remove the generic prompt exports once file-specific routing is wired (W2). At minimum, add a JSDoc note on the generic exports marking them as fallback. |
| W6 | claws-sdk/src/compile/index.ts | L86-106 | **`compile/index.ts` re-exports `AnthropicLLMProvider` (a concrete implementation) alongside pure interfaces.** The barrel exports both the provider-agnostic `LLMProvider` interface and the Anthropic-specific concrete class from the same entry point. This means any consumer importing from `@bic/claws-sdk/compile` transitively depends on the Anthropic SDK's type declarations even if they only need the interface. The whole point of the provider pattern is to keep the concrete implementation behind a separate import. | Move `AnthropicLLMProvider` to a separate subpath export (e.g., `@bic/claws-sdk/compile/anthropic` or `@bic/claws-sdk/llm/anthropic`). The main `compile` barrel should only export the interface and `ExtractorLLM`. |

---

## Summary

The LLM module has clean type boundaries and a correct provider-agnostic interface design, but **the pipeline is not wired end-to-end**: LLM results are extracted and discarded without passing through the verifier or merger, the file-specific prompts are dead code, and the `cache` CLI subcommand is unregistered. The raise-only security invariant has a gap in overlapping intent merges (M4). The watch command handler breaks the `createLLMProvider` adapter boundary (M1). All four Majors must be resolved before merge to satisfy CP-5 exit criteria.
