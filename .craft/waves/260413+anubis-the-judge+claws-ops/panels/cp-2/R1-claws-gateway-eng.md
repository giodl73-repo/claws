| M1  | claws-sdk/src/doctor/checks/policy-syntax.ts                             | L19              | **Policy validation schema mismatch with templates.** The check requires fields `['name', 'version', 'rules']` (L19), but all four templates (soc2, hipaa, eu-ai-act, minimal) generate policies with top-level fields `policy`, `framework`, `level`, `rules` -- they never produce `name` or `version`. Running `claws doctor` after `claws init --template soc2` will report every generated policy as invalid (missing `name, version`). This is a gateway-blocking issue: users who init-with-template and immediately run doctor will get false-positive errors.                                                                                   | Change REQUIRED_FIELDS to `['policy', 'level', 'rules']` to match the schema templates actually emit, or add `name` and `version` fields to every template policy. The former is less disruptive.                                                   |
| M2  | claws-sdk/src/init/platform-detect.ts                                    | L38-43           | **Glob patterns silently skipped -- dotnet and .sln detection broken.** Markers `*.csproj` and `*.sln` are glob patterns that are intentionally skipped at L71 (`if (marker.file.includes('*')) continue`). This means dotnet and Java-by-sln workspaces can never be detected. The WORKSPACE_MARKERS array promises dotnet/sln support but the implementation silently drops them. This impacts `claws init` on dotnet workspaces -- they'll always detect as `unknown`.                                                                                                                                                                                | Either implement glob matching for these patterns (e.g. `readdir` + filter), or replace globs with concrete representative filenames like `Directory.Build.props` or check for the existence of any `*.csproj` file via a readdir scan.             |
| M3  | claws-sdk/src/init/gitignore-update.ts vs claws-sdk/src/types/sidecar.ts | L14-17 vs L69-74 | **Gitignore coverage gap: init protects fewer directories than CLAWS_GITIGNORE_DIRS specifies.** `CLAWS_GITIGNORE_DIRS` in sidecar.ts lists `.claws/keys`, `.claws/secrets`, `.claws/cache`, `.claws/runtime` (4 directories). But `updateGitignore` in gitignore-update.ts only adds `.claws/keys/` and `.claws/secrets/` (2 directories). The `.claws/cache/` and `.claws/runtime/` directories may contain sensitive data or runtime state but are not protected by the workspace-level .gitignore. `initSidecar` writes its own `.claws/.gitignore` internally, but that only applies if git tracks `.claws/` as a subtree, which many setups won't. | Import `CLAWS_GITIGNORE_DIRS` from sidecar.ts and derive `REQUIRED_GITIGNORE_ENTRIES` from it instead of hardcoding 2 of 4 directories.                                                                                                             |
| M4  | claws-sdk/src/amend/apply.ts                                             | L23-33           | **OC_PROTECTED_FILES missing `skills/` directory.** The protected list guards 7 individual files plus `lobster.yaml` but omits the `skills/` directory (the 9th OC source in DEFAULT_FILE_SOURCES). The lossless-OC-fidelity guarantee ("claws NEVER modifies original OC files") has a gap: an amendment could theoretically write to `skills/SKILL.md` without triggering a protection check.                                                                                                                                                                                                                                                          | Add `'skills/'` to OC_PROTECTED_FILES, or better, derive the list from `DEFAULT_FILE_SOURCES` so it can never drift.                                                                                                                                |
| M5  | claws-cli/src/commands/amend.ts                                          | L88-93           | **Recompile stub always returns success -- amendment apply skips verification.** The recompile callback is a no-op stub that always returns `{ success: true }`. The amend pipeline contract requires recompilation after apply to verify GovernanceIR consistency. With this stub, an amendment could put the workspace into an inconsistent state where `claws.json`/`.claws/staging/` and the compiled IR disagree. This is a production correctness issue: the post-apply verification step exists for safety, and the stub silently disables it.                                                                                                    | Wire in the actual compile pipeline (`parse` + `compile` from the SDK) or at minimum validate the IR from disk after apply. If full recompile is deferred to a future pulse, add a prominent TODO with a tracking reference and emit a CLI warning. |

### Warning (W)

| #   | File                                     | Line/Section | Finding                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Suggested fix                                                                                                                                                        |

| W1  | claws-sdk/src/watch/watcher.ts           | L155-156     | **Non-recursive directory watch misses nested skills.** The `watchDirectory` method explicitly avoids recursive watching ("non-recursive, since Node's recursive option is not reliable on all platforms"). For `skills/`, this means nested skill directories (`skills/subdir/SKILL.md`) won't trigger watch events. The comment correctly notes the Node.js limitation, but the consequence is that `claws watch` silently misses changes in nested skill directories.                                                                             | Document this limitation in the watch CLI help text, or add a depth-2 directory scan to watch immediate subdirectories of `skills/`.                                 |
| W2  | claws-sdk/src/watch/auto-analyze.ts      | L97          | **Auto-analyze `run()` is synchronous but calls compile pipeline which may be CPU-heavy.** The `run` method is sync (`run(parseResult: ParseResult): AutoAnalyzeResult`) and runs the full governance pipeline: intent extraction, AST build, extract, manifest build, registry creation, and analyze. On large workspaces this could block the Node event loop during the 300ms debounce callback, starving the watcher and causing missed events. The gateway-eng 50ms latency budget applies here: governance analysis is a guest in the runtime. | Make `run` async, or at minimum measure the duration and emit a warning if it exceeds 50ms. The `durationMs` field is already tracked -- add a threshold check.      |
| W3  | claws-sdk/src/init/bypass.ts             | L97-104      | **Bypass audit record lacks user/PID/hostname context.** The BYPASS_ACTIVATED event records only `type`, `timestamp`, and `env`, but not who activated bypass or from which process. For R3+ environments, fleet compliance auditors need to know which user or process activated bypass.                                                                                                                                                                                                                                                            | Add `pid: process.pid`, `user: os.userInfo().username` (or equivalent), and `hostname: os.hostname()` to the audit event.                                            |
| W4  | claws-sdk/src/doctor/migrate/v1-to-v2.ts | L35          | **Default `fleet.allowBypass: false` is fail-closed for R1-R2 contexts.** The v2 defaults set `fleet: { allowBypass: false }`, which means a v1-to-v2 migration immediately locks out CLAWS_BYPASS. Per the gateway-eng role definition, R1-R2 should fail-open. A workspace at trust tier T2 migrating to v2 loses bypass capability with no warning.                                                                                                                                                                                               | Set `fleet.allowBypass` default based on the existing trust tier: `true` for T1-T2, `false` for T3+. Or at minimum, default to `true` and let fleet policy override. |
| W5  | claws-sdk/src/watch/debounce.ts          | L51          | **Debouncer resets timer on every event -- rapid continuous edits can starve batch emission indefinitely.** If events arrive faster than the 300ms window (e.g. a formatter rewriting many files), the timer keeps resetting and no batch ever fires until the writes stop. This means a long formatting run could delay violation detection for the entire duration + 300ms.                                                                                                                                                                        | Use a max-wait threshold (e.g. 2s) in addition to the reset-on-last-event pattern, so batches fire within bounded time regardless of event rate.                     |
| W6  | claws-sdk/src/init/uninstall.ts          | L99-103      | **Backup uses `cp` which may fail with `EPERM` on Windows for locked files.** `.claws/runtime/` or `.claws/cache/` files may be locked by another process (e.g. an active `claws watch`). The `cp()` call will throw, aborting the uninstall and leaving partial state. The error is caught by the CLI but the user gets a generic "write permissions" message.                                                                                                                                                                                      | Catch per-file copy errors gracefully, skip locked files with a warning, and continue with the rest of the backup. Or stop the watcher before uninstalling.          |
| W7  | claws-sdk/src/init/config-create.ts      | L36-42       | **Template config overrides are not merged into the init config.** `buildInitConfig` accepts a `template` parameter but only sets `template: name` as a field. The template's `configOverrides` (e.g. `trustTier: 3` for SOC2) are never applied to the written config. This means `claws init --template soc2` writes `trustTier: 2` (default) instead of `trustTier: 3` (SOC2 requirement).                                                                                                                                                        | Merge `template.configOverrides` into the config in the orchestrator after `buildInitConfig`, or pass the overrides into `buildInitConfig`.                          |

## Summary

From the gateway-eng perspective, the CP-2 implementation is architecturally sound: the SDK/CLI separation is clean, OC workspace files are protected by an explicit guard list, bypass is audit-recorded, and the watch pipeline (normalize -> debounce -> content-hash -> incremental-parse -> analyze -> recompile) is well-structured for Gateway performance. However, five major issues must be fixed before merge: (1) the policy-syntax doctor check will reject every template-generated policy due to a field name mismatch, (2) dotnet platform detection is silently broken, (3) gitignore coverage is incomplete vs the authoritative sidecar layout, (4) the OC protected files list has a gap on `skills/`, and (5) the amend recompile stub silently disables post-amendment verification. The most Gateway-critical warning is W7 -- template config overrides not being applied means SOC2/HIPAA trust tiers are silently downgraded to T2, which is a governance weakening that could ship unnoticed.
