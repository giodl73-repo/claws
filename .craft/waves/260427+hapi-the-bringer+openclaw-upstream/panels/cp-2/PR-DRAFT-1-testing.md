## Strengths preserved

- **Issue-replay harness is the right shape** (`issue-replay.test.ts:33–102`) — fixture-driven, asserts both `expectsCodes` AND `forbidsCodes`, with `notes` documenting the failure pattern. The negative cases (#14998 `$schema`, #62438 clean `${VAR}`) are exactly the false-positive-rate-as-contract proof reviewers want — but the PR body needs to surface this.
- **Per-rule positive + negative pairing** (`rules-coverage.test.ts:20–291`) — 13 codes × 2 cases minimum, with edit-distance boundary tests for did-you-mean (rules-coverage:113–133). This is the test discipline the lint catalog needs.
- **`ocUri` populated on every finding asserted** (`issue-replay.test.ts:118–120`) — `expect(f.ocUri.startsWith('oc://config')).toBe(true)` for every finding across every replay. URI vocabulary contract is enforced at the suite level, not per-test.
- **null-as-absence semantics tested** (`rules-coverage.test.ts:220–238`) — required-key-present-but-null + optional-key-present-but-null distinguished. This is the kind of edge case bot-trio reviewers spot-check.

## Verdict reasoning

The lint-surface tests that _are_ written are good — discipline on negatives, fixture-driven replay against cited issues, schema DI silent-without-schema assertions. If this PR shipped only the lint surface and the `replaceConfigFile` conversion with the 47 lint tests + a real-config round-trip suite + the pulse 04 verification gate executed, it would be APPROVE-WITH-WARNINGS. The problem is the metrics line at L260 promises 70 tests, and the test plan at L181–235 enumerates 49 F-numbered checkboxes all marked `[x]` — including F-91/F-92 doctor migration emit, F-95/F-96/F-97 `resolveConfigUri` (function not implemented), F-99 perf bench (file does not exist), F-84 upstream backward-compat (cannot run claws-side). Marking `[x]` on a test plan claim is a stronger signal to reviewers than "tests TBD" — they'll check that the test exists, find it doesn't, and the trust dent shows up in every subsequent PR in the wave.

Pre-push gate is straightforward: either write the missing 23 tests and verify them green, or downgrade the test-plan checkboxes to `[ ]` for the unwritten ones and reframe the metrics line as "47 tests this commit, 23 follow-up commits before review". The first option is the contract; the second is honest. The current draft is neither.
