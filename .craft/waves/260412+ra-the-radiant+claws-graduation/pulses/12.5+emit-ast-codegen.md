# Pulse 12.5: Emit AST-Based Codegen — ts.factory Rewrite + tsc-Strict Gate

## Origin

Side-pulse added during CP-2 Round 1 review in response to user directive.
The OC emitter shipped in pulse 7 and the Claude Code emitter in pulse 8 both
concatenate TypeScript source via template strings. The R1 review found this
acceptable for correctness but not for the "real codegen" moat the product
depends on: the orphan `compiler/codegen/` module (pulse 9) produced type-heavy
TypeScript AST output but had zero consumers and was deleted in CM-9.

User ruling: "we throw away both and rewrite OC/CC to have all the nice stuff...
lets get it right. i didnt realize we were stuck here."

## Objective

Replace template-string TypeScript generation in the OC emitter with proper
AST-based codegen using the TypeScript Compiler API (`ts.factory.*`). Add a
tsc-strict round-trip e2e test that compiles every emitted TypeScript file and
asserts zero diagnostics. Establish the quality bar codified in
`CL-14-emitter-architecture` for every future emitter.

Claude Code emits Markdown + JSON (not TypeScript), so the CC quality pass is
scoped to task #15 (Zod schema for `settings.json` + typed CLAUDE.md builder).

## Non-goals

- CC emitter Zod/schema refactor — deferred to task #15 (separate pulse TBD)
- Paid-tier emitters (Bedrock / CrewAI / LangGraph / Cursor / Copilot) — their
  scenarios stay in `design/claws/scenarios/` as deferred work; when those
  emitters land they inherit the CL-14 quality bar from day one
- Public-API export of `ts-builder.ts` — per CL-14 v1.1 §3.2, `ts-builder.ts`
  IS exported via public subpath `./compiler/emit/ts-builder` for consumption
  by paid-tier emitter packages in `@bic/claws-sdk`. This is required because
  CL-13 places paid-tier emitters in a separate package and "internal-only"
  across-package imports are impossible. The subpath is documented as
  "extension-only" and not under the stability guarantees of the public
  `compile()` surface. (This reverses the v1.0 non-goal; see CL-14 v1.1
  change log.)

## Scenarios

- `emit-ast/S01` — OC emitter produces valid TypeScript via ts.factory (no
  template strings in output path; every file is a SourceFile that round-trips
  through ts.createProgram)
- `emit-ast/S02` — tsc-strict round-trip gate catches template-string
  regressions (synthetic broken AST → gate fails)
- `emit-ast/S03` — determinism holds across AST-printed output (two compiles
  produce byte-identical TypeScript)
- `emit-ast/S04` — marker header (`// claws-governance:oc-gateway:v{version}`)
  is on line 1 of every emitted TS file; AST printer preserves position
