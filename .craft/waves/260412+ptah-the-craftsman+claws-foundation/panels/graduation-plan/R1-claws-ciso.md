| M1  | claws-sdk-graduation.md | Freemium Boundary                    | **Basic HMAC audit chain in the free tier is cryptographically insufficient and creates liability.** HMAC-SHA256 requires a shared secret. Who holds the key? If the user holds it, they can rewrite the entire audit chain -- it's not tamper-proof, it's tamper-evident only to the key holder. If claws holds it, the free tier has a key management dependency on a service that doesn't exist in the plan. An auditor will ask "can the developer modify this audit trail?" and the answer with HMAC is "yes, trivially." This isn't a security feature -- it's security decoration that could be cited in an incident report as evidence of negligence ("they had audit, it was useless"). | Replace HMAC with Ed25519 signing in the free tier using a locally-generated keypair. The user generates a keypair at `claws init`, the public key is embedded in the sidecar, and audit entries are signed with the private key. This gives non-repudiation for single-user scenarios without requiring RFC3161 timestamps (which remain paid). The crypto cost is negligible -- Ed25519 signs ~60K messages/sec.                                                                                                     |

Every claws-compiled agent should enforce R5 fail-closed, regardless of tier.                                                                         | Move a minimal GovernanceManager (single-agent, local enforcement, R5 fail-closed) into the free tier. The paid tier extends with fleet-wide enforcement, centralized policy, and compliance reporting. R5 is not a premium feature -- it is the minimum viable security posture.                                                                                                                                                                                                                                      |

They'll see HMAC audit entries that no auditor will accept. They'll conclude "claws audit is weak" and move on -- they won't discover that the paid tier has Ed25519 + RFC3161. The free tier's weak audit actively harms paid-tier sales because it's the first thing a security team evaluates.                                                                                                                                                                                                  | The free tier audit must be strong enough that a security evaluator says "this is solid for single-user, and the enterprise tier adds fleet + timestamping + SIEM." Ed25519 local signing (M1) achieves this. | M4  | claws-sdk-graduation.md | What Stays as Dependency (Paid Tier) | **The `export * from '@claws/compiler'` pattern in the paid tier violates supply-chain security principles.** The paid tier (`@bic/claws-sdk`) re-exports everything from a public npm package (`@claws/compiler`). A supply-chain attack on the public package (typosquatting, maintainer compromise, dependency confusion) propagates directly into every enterprise deployment. There is no integrity verification, no signature checking, no vendoring. For a product that sells governance and compliance, having its own supply chain be ungoverned is a credibility-destroying contradiction.                                                                                             | Add supply-chain hardening: (1) `@bic/claws-sdk` pins exact versions of `@claws/compiler` with integrity hashes in package-lock.json, (2) CI verifies npm package signatures before publish, (3) consider vendoring the compiler source into the enterprise package at build time so enterprise customers never resolve from public npm at runtime.                                                                                                                                                                    |
| M5  | claws-sdk-graduation.md | Phase 1 scope                        | **Crypto internalization ("use Node.js crypto directly, ~150 lines") understates the security engineering required.** Cryptographic code is not measured in lines -- it's measured in correctness. The plan proposes rewriting HMAC-SHA256, SHA-256, and signing using Node.js crypto directly. This means: key derivation, constant-time comparison, secure random generation, encoding handling (hex vs base64 vs buffer), and error handling for crypto failures. A single bug (e.g., non-constant-time HMAC comparison) creates a timing side-channel. "~150 lines" implies this is trivial. It is not.                                                                                      | (1) Do not rewrite crypto from scratch. Wrap Node.js crypto primitives in a thin, heavily-tested module with explicit constant-time comparison (`crypto.timingSafeEqual`). (2) Add a dedicated security review gate for the crypto module before it ships. (3) Target 100% branch coverage on the crypto module with explicit test cases for timing attacks, encoding mismatches, and key rotation. (4) Consider using `@noble/ed25519` or `@noble/hashes` which are audited libraries rather than raw Node.js crypto. |

## Summary

The graduation plan has a fundamental security architecture problem: it ships governance artifacts (GovernanceIR types, audit chain, 29 rules, 12 test checks) in the free tier without the runtime enforcement (GovernanceManager, R5 fail-closed) that makes those artifacts meaningful. This creates governance theater -- users believe they are governed when they are not. The HMAC audit chain (M1) is not tamper-proof, R5 fail-closed is absent from the free tier (M2), the weak audit harms paid-tier sales (M3), and the supply chain is ungoverned (M4). The crypto internalization is under-scoped (M5). The minimum fix: move Ed25519 signing and R5 fail-closed into the free tier. These are not premium features -- they are the minimum security posture for any tool that claims to provide governance. The paid tier differentiates on scale (fleet, SIEM, compliance reporting) and depth (RFC3161, OIDC/SAML, policy evaluation), not on basic security.
