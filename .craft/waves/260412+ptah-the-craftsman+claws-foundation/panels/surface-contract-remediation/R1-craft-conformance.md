# R1 Conformance Review -- Surface Contract Remediation Plan

**Reviewer**: craft:conformance
**Scope**: .craft/plans/surface-contract-remediation.md
**Date**: 2026-04-12
**Verdict**: CONDITIONAL PASS (4M, 3W, 3N)

---

## Summary

The plan correctly identifies 7 DC check failures and proposes a phased remediation. However, the root cause diagnosis for DC-01 is wrong (the actual failures are non-headline atoms with non-null narrative, not headline atoms missing narrative). The plan also misidentifies which areas contain the parse errors (claims "2 works" but works has 0 failures). The DC-04 strategy of known-gaps.yaml is architecturally sound but needs tighter acceptance criteria. The DC-03 target of <20 is too loose -- the schema exists to enforce classification and the target should be 0. DC-11's proposed `reuses:` mechanism does not exist in the validation code, creating a spec-to-code gap.

## Verdict

Four MUST-FIX issues need resolution before this plan can be executed:

1. **M1**: Correct the DC-01 root cause to "non-headline atoms with non-null narrative must be set to null" (not "headline atoms need narrative: platform").
2. **M2**: Correct the failure distribution: 6 claws + 1 craft/personas + 1 compiler/governance/role-system. Remove the claim of 2 works failures.
3. **M3**: Either add a task to implement `reuses:` field support in DC-11 validation code, or change the DC-11 fix strategy to pure atom deduplication (remove from non-authoritative area contracts).
4. **M4**: Change DC-03 target from <20 to 0. Every atom must be classified in exactly one area's surface contract.

After these corrections, the plan's phased approach and Phase 6 known-gaps strategy are sound.
